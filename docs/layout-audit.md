# Проверка удаления импорта CSS-club

Проверка относится к переносу `profile-content-layout-v1.css`, а не ко всему
CSS-club: импорт `custom_posters.min.css` намеренно сохранён. На момент аудита
перенос уже опубликован пользователем через согласованную процедуру.

## Что проверяет инструмент

`audit.mjs` читает CSSOM реального `style#custom_css` после подстановки и сравнивает
его с десятью правилами из `vendor/profile-content-layout-v1.css`:

- каждое правило существует ровно один раз в пользовательской части;
- в импортированной основе этих правил нет, метка удалённого импорта отсутствует;
- в других доступных таблицах стилей нет дополнительных точных копий;
- совпадают селекторы, объявления, `!important`, условия media и порядок десяти правил;
- все остальные правила, включая `::before`/`::after`, сохраняют порядок в CSSOM;
- остаётся тот же элемент стиля в той же позиции; хэш реально применённого текста
  совпадает с хэшем подготовленного кандидата.

Недоступная для чтения таблица стилей не игнорируется: она записывается в отчёт,
и строгий аудит не выдаёт PASS. При этой проверке таких таблиц не было.

Положение блока относительно всей старой основы **не сохранилось буквально**:
раньше раскладка стояла перед импортом постеров, теперь — после него, в начале
пользовательской части. Проверка доказывает сохранность специфичности, условий
и внутреннего порядка блока, а также порядка остальных правил. Отсутствие влияния
перестановки подтверждено текущим DOM, геометрией и вычисленными свойствами
на заданных ширинах; это не гарантия для всех будущих состояний сайта.

Пересечения с постерами и AUTO-sticky затем отдельно проверены в
[аудите порядка](cascade-order-audit.md). Для текущих версий перестановка принята
на основании разбора приоритетов и проверки состояний.

## Запуск

```powershell
# Строгая проверка эквивалентности перенесённой раскладки:
# PASS → код 0, FAIL → код 1, снимки и JSON сохраняются в обоих случаях.
node .\tools\preview\preview.mjs --check-layout

# Локальные проверки, включая намеренные пропуски и дубли:
pnpm --dir tools/preview test
```

Без `--check-layout` предпросмотр остаётся диагностическим: он показывает отличия,
но не объявляет любую намеренную смену оформления ошибкой процесса.
Строгий режим проверяет эквивалентность именно текущему эталону раскладки.

## Проверка старой основы и намеренной ошибки

Чтобы результат не был тривиальным после публикации, повторно использован реальный
`published-compiled.css`, сохранённый перед переносом. Исходник с прежним импортом
восстановлен во временном файле. Его соответствие сохранённому CSSOM проверяется
до запуска. Это повтор старого CSS на текущем DOM, а не сохранённая старая страница.

```powershell
# Нужен сохранённый снимок ДО переноса, содержащий метку прежнего импорта.
node .\tools\preview\make-audit-fixtures.mjs .preview\2026-10-24T18-51-55-602Z\published-compiled.css

# Положительный сценарий: старый импорт удаляется, локальная копия остаётся.
node .\tools\preview\preview.mjs --check-layout `
  --baseline-css .preview/layout-audit-input/historical-source.css `
  --baseline-compiled .preview/layout-audit-input/historical-compiled.css

# Намеренно отрицательный сценарий: во временной копии пропущено правило .c-left.
# Ожидается FAIL и код 1; это успешное обнаружение специально внесённой ошибки.
node .\tools\preview\preview.mjs --check-layout `
  --css .preview/layout-audit-input/missing-rule.css `
  --baseline-css .preview/layout-audit-input/historical-source.css `
  --baseline-compiled .preview/layout-audit-input/historical-compiled.css
```

Эти команды не редактируют `styles_optimized.css`, не используют OAuth, не отправляют
CSS через API и ничего не публикуют. Временные исходники, снимки и отчёты находятся
только в игнорируемой `.preview/`.

## Результаты

Все три сценария выполнены на 1440, 390 и 360px. Корректный CSS прошёл проверку
и с текущей, и со старой основой: по одной локальной копии каждого правила,
ноль копий в оставшейся основе и других листах, без изменений проверенных размеров
и свойств. В историческом сценарии десять правил действительно исчезли из основы
и появились в пользовательской части. Сохранены 605 правил псевдоэлементов.

В намеренно испорченной копии пропущено полное правило
`#profiles_show .profile-content > .cc-2 > .c-left`. Итог на всех ширинах — FAIL:
в итоговом CSS нет ни локальной, ни оставшейся импортированной копии этого правила.
На 1440px изменяется геометрия 274 узлов. На 390/360px геометрия совпадает,
поскольку правило действует только от 768px, но проверка структуры всё равно
обнаруживает пропуск. Скриншоты сами по себе не смогли бы доказать полноту переноса.

Локальные тесты также обнаруживают двойную локальную копию, оставшуюся старую
основу, маскирующую пропуск, и дубль в отдельном `<style>`. Все восемь тестов прошли.

В инструментах исправлены пробелы: добавлены структурный аудит и код возврата FAIL,
обход CSSStyleRule с пустым `cssRules` (современная модель CSS nesting), сравнение
псевдоэлементов с обеих сторон и продолжение проверки остальных ширин при разных
размерах снимков компонента. Разные размеры теперь записываются как диагностический
сигнал; изображения дополняются до общего холста для pixel diff.

Сравнение пикселей остаётся вспомогательным: WebP/GIF продолжают менять кадры.
Проверка Firefox, реальных телефонов, состояний hover/focus, движения анимаций,
всех страниц сайта и точной будущей серверной очистки в этот аудит не входит.
