# Устройство темы и переход к модулям

## Сейчас

В Shikimori устанавливается содержимое `styles_optimized.css`: внешние импорты
и собственные настройки. Путь к этому файлу пока сохранён, чтобы не ломать ссылки.
`scripts/deploy.ps1` публикует локальный CSS через API независимо от видимости GitHub.

Большая часть основы находится в сторонних файлах. Проверенный 24 октября 2026 года
результат серверной компиляции содержал примерно 17 300 строк; около 15 900 из них
приходились на четыре основных файла E-design. Количество строк не измеряет нагрузку
отрисовки, а минификация сама по себе не отменяет дорогие эффекты.

## Целевая структура CSS

Следующая структура — план. Первый снимок внешней раскладки уже сохранён в
`vendor/profile-content-layout-v1.css`, а его правила перенесены в локальный блок
основного CSS. Отдельные исполняемые `css/`-модули ещё не выделены:

```text
vendor/                   Зафиксированные версии сторонней основы
css/
  palette.css             Цвета и переменные
  navigation.css          Меню, логотип, поиск
  profile.css             Расположение блоков профиля
  achievements.css        Достижения и франшизы
  filters.css             Фильтры
  effects.css             Рамки и анимации
```

Первая стадия — зафиксировать исходники с указанием авторов, версий, контрольных сумм
и условий использования. Затем перенести собственные правила, сохранив порядок,
приоритеты и значения. Замена сторонней основы своими компонентами должна происходить
по одному разделу, с проверкой всего сайта, а не только главной страницы профиля.

## Импорты и версии

Планируется перечислять абсолютные `@import` модулей непосредственно в редакторе
Shikimori. Импорт одного CSS-манифеста с вложенными импортами пока не проверен.

В опубликованном, но архивированном исходном коде Shikimori обработчик загружает
импорты верхнего уровня, а загрузчик кэширует содержимое по URL на восемь часов.
Это объясняет необходимость проверки текущего сервера перед модульной миграцией;
архивный код не гарантирует нынешнюю реализацию сайта.

Для воспроизводимых публикаций предпочтительны ссылки на конкретный commit SHA,
а не на изменяемую ветку. Тогда новый релиз получает новые URL, а откат возвращает
прежний набор ссылок. Нужно учитывать относительные URL ресурсов и порядок правил.

Поэтапный план, первый перенос раскладки и результаты визуальной проверки описаны
в [журнале миграции](style-migration.md).

Публичность репозитория не превращает git push в мгновенное обновление профиля:
действуют компиляция и кэширование Shikimori. Текущий процесс подтверждаемой публикации
через API остаётся полезен и для будущего списка импортов.

## Что проверять при замене основы

- Главная страница профиля, достижения и избранное.
- Список аниме, каталог, фильтры и раскрытые списки.
- Меню, поиск, комментарии и подсказки.
- Наведение, фокус клавиатуры и состояние без авторизации.
- Широкий и узкий экран; первая прокрутка после обновления.
