# Устройство темы и переход к модулям

## Сейчас

В Shikimori устанавливается содержимое `styles_optimized.css`: внешние импорты
и собственные настройки. Путь к этому файлу пока сохранён, чтобы не ломать ссылки.
`scripts/deploy.ps1` публикует локальный CSS через API независимо от видимости GitHub.

Большая часть основы находится в сторонних файлах. Проверенный 24 октября 2026 года
результат серверной компиляции содержал примерно 17 300 строк; около 15 900 из них
приходились на четыре основных файла E-design. Количество строк не измеряет нагрузку
отрисовки, а минификация сама по себе не отменяет дорогие эффекты.

## Целевая структура CSS

Следующая структура — план. Первый снимок внешней раскладки уже сохранён в
`vendor/profile-content-layout-v1.css`, а его правила перенесены в локальный блок
основного CSS. Для пилота создана идентичная исходнику рабочая копия
`css/base/main_code_3.css`; она пока не подключена. Остальная структура ниже — план:

```text
vendor/                   Зафиксированные версии сторонней основы
css/
  base/main_code_3.css     Подготовленная копия E-design для прямого импорта
  palette.css             Цвета и переменные
  navigation.css          Меню, логотип, поиск
  profile.css             Расположение блоков профиля
  achievements.css        Достижения и франшизы
  filters.css             Фильтры
  effects.css             Рамки и анимации
```

Первая стадия — зафиксировать исходники с указанием авторов, версий, контрольных сумм
и условий использования. Затем перенести собственные правила, сохранив порядок,
приоритеты и значения. Замена сторонней основы своими компонентами должна происходить
по одному разделу, с проверкой всего сайта, а не только главной страницы профиля.

## Импорты и версии

Выбрано перечислять абсолютные `@import` модулей непосредственно в редакторе
Shikimori, по commit SHA своего репозитория. Шрифты остаются внешними импортами.
Импорт одного CSS-манифеста с вложенными импортами пока не проверен.
Первый пилот и условия подключения — [owned-import-pilot.md](owned-import-pilot.md).

В опубликованном, но архивированном исходном коде Shikimori обработчик загружает
импорты верхнего уровня, а загрузчик кэширует содержимое по URL на восемь часов.
Это объясняет необходимость проверки текущего сервера перед модульной миграцией;
архивный код не гарантирует нынешнюю реализацию сайта.

Для воспроизводимых публикаций предпочтительны ссылки на конкретный commit SHA,
а не на изменяемую ветку. Тогда новый релиз получает новые URL, а откат возвращает
прежний набор ссылок. Нужно учитывать относительные URL ресурсов и порядок правил.

Поэтапный план, первый перенос раскладки и результаты визуальной проверки описаны
в [журнале миграции](style-migration.md).

Публичность репозитория не превращает git push в мгновенное обновление профиля:
действуют компиляция и кэширование Shikimori. Текущий процесс подтверждаемой публикации
через API остаётся полезен и для будущего списка импортов.

## Что проверять при замене основы

- Главная страница профиля, достижения и избранное.
- Список аниме, каталог, фильтры и раскрытые списки.
- Меню, поиск, комментарии и подсказки.
- Наведение, фокус клавиатуры и состояние без авторизации.
- Широкий и узкий экран; первая прокрутка после обновления.

## Известные особенности CSS и разметки

Наблюдения сессии 24–25 октября 2026 года. Читать при работе с соответствующим
компонентом; это не гарантия будущей разметки Shikimori.

- Shikimori предварительно обрабатывает CSS: в изученной странице содержимое внешних
  импортов было развёрнуто в `<style id="custom_css">` перед собственными правилами.
  Поэтому наличие `@media` перед `@import` в исходнике не доказывает, что импорты
  на сайте не работают. Отделяй стандартное поведение браузера от обработки Shikimori.
- Основа: четыре `main_code_*.css` E-design, дополнения истории и графика,
  CSS-club для расположения профиля и замены постеров, Google Fonts.
  Импортированные правила задают важные размеры, позиционирование и приоритеты.
- Новые фильтры используют `.c-ms`, `.c-ms-dropdown`, `.c-ms-option`,
  `.c-ms-option-mark`; выбранный пункт в присланной разметке имел класс `.is-on`.
- Шапка фильтров — `.b-collection-filters .c-filters-head`; ссылка сброса находится
  в `.misc-links`. Тема превращала эту область в круглые кнопки шириной 100%.
  Точечное переопределение уже убирает лишние псевдоэлементы и выравнивает текст.
  Боковые `margin: 4px` общего `.subheadline` здесь также сброшены.
- Реальный класс избранного — `.cc-favourites`. Содержимое достижений находится
  в `.achievements > .cc-2`; основной заголовок — отдельный `.subheadline`.
- В текущей разметке `.about.block > div` скрывает заголовок и кнопку редактирования,
  а содержимое TOP находится в `<center>` и остаётся видимым.
- Замены картинок используют псевдоэлементы, иногда с `z-index: -1`.
  Изоляция рисования и новые stacking context могут повлиять на их видимость.

Накопленные ошибки `*/`, `}` и `color: inhirit` не исправлять попутно:
это может восстановить ранее игнорируемое правило и изменить оформление.
Импортный prefix `style#custom_css` и пользовательскую часть нужно различать;
точный способ проверки — [preview.md](preview.md).

Все четыре источника E-design зафиксированы на конкретный upstream-коммит;
исходные копии и контрольные суммы сохранены. Правила пока внешние.
Для main1/main4 проверены конкретные серверные URL-преобразования:
[аудит](edesign-url-audit.md). Первый собственный модуль подготовлен локально,
но основной CSS ещё использует прежние ссылки.
