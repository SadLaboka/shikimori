## Первоначальная проверка двух файлов

У первого файла FontAwesome содержит исходные пути `/\x/...`; в опубликованном
CSS они становятся протокол-относительными URL. Один фон переписан через Camo.
У мобильного файла также есть изменения URL ресурсов, в том числе Camo.
Это наблюдения серверной обработки, не доказательство ошибки или изменения картинок.
На первом этапе main1 и main4 оставлены на master до отдельной проверки.
Она затем выполнена в [аудите URL](edesign-url-audit.md); общей модели санитайзера нет. Защита не игнорирует URL
при сравнении ради формального PASS.

У main2 и main3 CSSOM совпал целиком. Их ссылки заменены с `/master/` на полный SHA,
на том же хосте и в том же порядке. Декларации, media, псевдоэлементы, переменные,
анимации и ресурсные URL не менялись. Это не локализация правил и не оптимизация
отрисовки; фиксация исключает автоматическое обновление двух выбранных файлов.
Остальная основа всё ещё может изменяться независимо от репозитория.

## Исходники и проверка

`vendor/edesign/main_code_2.css` и `main_code_3.css` — полные неизменённые снимки.
Авторство и исходные комментарии сохранены. Это эталоны, они не подключаются
дополнительно. Контрольные суммы и разрешённые пары URL находятся в
`vendor/edesign-pins.json`. Для этих снимков `.gitattributes` задаёт LF, чтобы
checkout на Windows не менял байтовые SHA256.

Предпросмотр поддерживает отдельную узкую операцию фиксации версии:

1. Число и порядок импортов сохраняются; допустимы только пары из манифеста.
   Произвольный SHA, перестановка и откат к master запрещены; main1/main4
   добавлены в текущий манифест после отдельного аудита URL.
   Этот путь не совмещается с удалением импорта или иной миграцией.
2. Перед применением сравниваются SHA256 локального снимка и точного ответа
   публичного pinned-URL с ожидаемой суммой, затем CSSOM снимка и наблюдаемого блока.
3. В foundation меняются только комментарии-метки URL; содержимое и позиции правил
   сохраняются. Новый лист поверх старого не накладывается.
4. Проверяются модель baseline, точный полный CSSOM, реальные свойства и геометрия.
   Отрицательные тесты обнаруживают повреждённый снимок/ответ, чужой SHA и перестановку.

Верификация выполняется и когда опубликованный источник уже содержит pinned-URL.
Если внешний файл недоступен или хэш не совпадает, запуск останавливается.
Новых зависимостей, MCP и сборщика нет; deploy/OAuth не менялись.

## Запуск

```powershell
pnpm --dir tools/preview test
node tools/preview/preview.mjs --check-layout --widths 1440,390,360
node tools/preview/preview.mjs --component history --widths 1440,390,360
```

Режим истории здесь — обычное сравнение геометрии/стилей и структуры, без повторного
набора интерактивных состояний q03. Такой набор не требуется для замены только
меток источников при совпадении всего CSSOM. Это не новое доказательство покрытия
всех страниц Shikimori или будущей серверной компиляции.

## Дальнейший перенос

Наблюдаемые преобразования URL main1/main4 затем проверены отдельно. Выбирать компоненты для локализации с сохранением порядка всего
каскада. Удалять часть правил из внешнего импорта напрямую нельзя: нужен полный
проверенный источник-замена или иной отдельно обоснованный способ. Эта фиксация
не разрешает автоматически такой рефакторинг, публикацию или git push.

Firefox, физические устройства, авторизованный вид и будущая серверная загрузка
новых URL не проверены. Снимки сохраняются, кадры GIF/WebP не замораживаются;
pixel diff сам по себе не является вердиктом. Поскольку декларации не менялись
и машинные проверки охватывают полный CSSOM, дополнительный просмотр всех
скриншотов и повтор всех прежних hover/анимаций не требуются.
