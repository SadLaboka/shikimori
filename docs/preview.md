# Локальный предпросмотр CSS

Предпросмотр открывает публичный профиль в отдельном Chromium через Playwright,
заменяет CSS только в памяти этой вкладки и сохраняет сравнение. Публикация,
OAuth и `scripts/deploy.ps1` не используются. Тема профиля не изменяется.

Исходники собственных правил — `css/components/`. Перед предпросмотром собери
кандидат командой `node scripts/build-css.mjs --write --output .preview/candidate.css`
и передай `--css .preview/candidate.css`. Порядок работы — [components.md](components.md).
Во всех компонентах изолированы сторонние скрипты и fullscreen-реклама:
они могут асинхронно вставлять CSS и менять индекс листа во время сравнения.
Штатные скрипты Shikimori и ресурсы изображений/шрифтов разрешены; поведение
рекламы не относится к покрытию. Проверка позиции `custom_css` не ослабляется.

## Установка и запуск в Windows

Нужны Node.js 20+ и pnpm в PATH. Зависимости изолированы в `tools/preview/`.

```powershell
# Из корня репозитория: установка по lock-файлу
pnpm --dir tools/preview install --frozen-lockfile
pnpm --dir tools/preview exec playwright install chromium

# Основной прогон: 1440×900, 390×844 и 360×844
node .\tools\preview\preview.mjs

# Строгий аудит переноса раскладки: пропуск/дубли дают FAIL и код 1
node .\tools\preview\preview.mjs --check-layout

# График активности: q05, фазы и hover
node .\tools\preview\preview.mjs --check-layout --check-activity --widths 1440,390,360

# Механизм постеров: профиль, подсказки и реальные коллекции
node .\tools\preview\preview.mjs --check-layout --check-posters --widths 1440,390,360

# Страница истории: q03, совместимость и интерактивные состояния
node .\tools\preview\preview.mjs --component history --check-history --widths 1440,390,360

# Реальный каталог и состояния раскрывающихся фильтров
node .\tools\preview\preview.mjs --component catalog --check-filters --widths 1440,390,360

# Другой локальный CSS; путь считается от корня репозитория
node .\tools\preview\preview.mjs --css .preview\candidate.css

# Только нужные ширины; видимое окно на время прогона
node .\tools\preview\preview.mjs --widths 1440,390 --headed

# Проверки обработки CSS и замены в настоящем изолированном браузере
pnpm --dir tools/preview test
```

Если Node.js не добавлен в PATH, используйте полный путь к `node.exe`.
`--headed` показывает выполнение; браузер закрывается после сохранения результатов.
Это минимальный снимочный предпросмотр, без наблюдения за файлом в реальном времени.

### Диагностика времени

В конце запуска печатается компактная `Timing (ms)`, она же — `report.timings`.
Этапы: запуск Chromium, публичный GET стиля, навигация, GET импортов, CSSOM,
warmup, вычисленные стили ключевых узлов/компонента, снимки и PNG diff.
`captureAuditsMs` — суммарное время четырёх аудитов в capture.
Времена включают ожидание инструмента; warmup включает прокрутку, стили и загрузку
изображений. GET импортов может выполняться параллельно: сумма этапов не равна total.
Total начинается после загрузки модулей и заканчивается после закрытия браузера,
до записи итогового отчёта; внешнее время команды дополнительно включает эти расходы.
Отдельные state-сценарии входят в total, без собственной детализации их внутренних шагов.
Таймеры содержат только фиксированные имена, число вызовов и время, без HTTP-ответов.
Сбой после запуска браузера также сохраняет собранные времена; ошибка запуска
самого Chromium остаётся ошибкой команды без итогового отчёта.

Изображения, DOM, CSSOM и результаты состояний между capture не кешируются.
Каждый снимок и сравнение выполняются заново. Для PNG совпадающих размеров
используются исходные RGBA-буферы; белое дополнение при разных размерах сохранено.
Тест сравнивает байты diff с прежним алгоритмом, включая прозрачность и разные размеры.

## Каталог и фильтры

`--component catalog` открывает настоящий `https://shikimori.io/animes` и временно
устанавливает в его существующий `style#custom_css` опубликованную тему SadLaboka
или проверенного локального кандидата. Тема сначала считывается и проверяется
на профиле; пустой стиль анонимного каталога не является baseline нашей темы.
Перед каждой шириной загружается новый документ каталога. Пользовательский CSS
заменяется полностью в том же элементе на прежнем месте каскада, без наложения.

Измеряются сетка первой страницы, карточки и фильтры. Внешняя высота страницы
и меняющийся блок пагинации не являются критерием эквивалентности компонента.
Подгрузка страниц 2+ блокируется, как и сторонние скрипты/`mobile_fullscreen_ad.js`;
счётчики блокировок есть в отчёте. Шрифты, изображения и основной JS сайта разрешены.
POST и WebSocket по-прежнему запрещены. Аккаунт/токены не используются.

`--check-filters` разрешён только с `--component catalog`. На каждой ширине
проверяются начальное состояние, раскрытие панели штатной мобильной кнопкой,
focus контрола, открытый список рейтинга, hover и active пункта, выбранный пункт
и его hover, сохранённый после загрузки chip, список жанров. Получается 10
сравнений на ширину. Ноль мишеней, скрытая панель без штатного открытия,
сброшенный CSS или несработавшее состояние не дают PASS.

Состояния сравнивают геометрию и 47 свойств нормального элемента и `::before`/`::after`
для всех потомков фильтров и первых трёх карточек. Полный список свойств сохранён
в `filters.json`; основной снимочный проход дополнительно сравнивает все вычисленные
свойства узлов фильтров/карточек. При выборе пункта сайт применяет фильтр после
закрытия списка и перестраивает документ; тест повторно устанавливает тему после
GET, проверяя точное содержимое листа. Chip закрывается кликом снаружи: клик по
самому выбранному chip переключает включение/исключение и не равен закрытию списка.

При обеих подстановках симметрично сбрасывается кэш раскладки кратким отключением
листа и синхронным layout flush. Это устраняет наблюдаемый сдвиг float/margin
каталога при эквивалентном CSS в Chromium; CSS, DOM, положение листа и допуски
не меняются. Снимки делаются после восстановления и стабилизации стиля.

Результаты: общий `index.html`, отдельные `filters.html`/`filters.json` и снимки
открытого/выбранного рейтинга и жанров. FAIL каталога даёт код 1, в том числе
без `--check-filters`. `--check-layout`, `--check-history`, `--check-posters`
и `--check-activity` в каталоговом режиме отклоняются.

Это не проверка всех сочетаний фильтров: поиск по спискам, прокрутка внутри них,
исключение пунктов, удаление chip, сброс и авторизованный «Мой список» не покрыты
сценарием. Рекламный интерфейс и бесконечная прокрутка исключены намеренно.
Мобильные снимки сохраняют существующий дизайн, а не подтверждают его удобство.
Результаты и отрицательный контроль: [catalog-filters-audit.md](catalog-filters-audit.md).

Для изменений дизайна и оптимизации строгий миграционный PASS не всегда применим:
перегруппировка одинаковых кадров тоже меняет CSSOM. Как выбирать целевые проверки,
сохраняя защиту миграции, описано в [design-workflow.md](design-workflow.md).

## Что именно подменяется

1. Скрипт читает публичный исходник собственного стиля через **GET**
   `https://shikimori.io/api/styles/1343722`, проверяет владельца и открывает профиль
   `https://shikimori.io/SadLaboka` без авторизации. Токены не нужны и не читаются.
2. В опубликованном `style#custom_css` должна быть ровно одна граница
   `/* User Custom Styles */`. Всё перед ней сохраняется побайтно как основа.
3. Из локального файла извлекаются `@import`. Их список и порядок должны совпасть
   с опубликованным исходником и метками импортов внутри основы. Есть одно явное
   исключение: перенос `profile-content-layout-v1.css` в блок `BEGIN/END LOCAL
   PROFILE LAYOUT`. Только этот исходный блок удаляется из тестовой основы;
   его CSSOM предварительно сверяется с сохранённым снимком в `vendor/`.
   Также поддержан полный перенос `q03_history_bookmarks.css` в блок
   `BEGIN/END LOCAL HISTORY BOOKMARKS`, со снимком `vendor/q03_history_bookmarks.css`.
   Также поддержан q05 в `BEGIN/END LOCAL ACTIVITY GRAPH` со снимком
   `vendor/q05_animated_activity_graph.css`. За один запуск разрешено удалить
   только один из четырёх известных импортов. Четвёртый — `custom_posters.min.css`
   в `BEGIN/END LOCAL CUSTOM POSTERS`, со снимком `vendor/custom_posters.min.css`;
   любое другое изменение импортов останавливает запуск, кроме проверенной
   фиксации версий E-design из `vendor/edesign-pins.json` или точного переноса
   источника из `css/imports.json` (описаны ниже).
4. Для опубликованного исходника строится пробный результат локальной обработки.
   Его CSSOM — правила после разбора браузером — сравнивается с CSSOM реальной
   страницы. При несовпадении замена запрещается. Временный лист для проверки
   имеет `media="not all"` и сразу удаляется.
5. Затем содержимое **того же** `style#custom_css` заменяется на проверенную основу,
   ту же метку границы и подготовленную локальную часть. Позиция в каскаде сохраняется.
   Старые пользовательские правила удаляются: это не дополнительный CSS поверх них.
   При миграции остальные импортированные блоки сохраняются побайтно; перенесённая
   раскладка теперь находится после оставшегося импорта постеров, перед настройками.
6. Основа повторно сверяется, делаются снимки и проверяются вычисленные стили.
   В конце исходное содержимое возвращается, контекст и браузер закрываются.

В отдельном контексте нет cookies, `storageState` или профиля пользовательского
браузера. Сетевые запросы страницы, кроме GET/HEAD, блокируются; WebSocket закрывается.
Публичный GET исходника выполняется отдельно через контекст Playwright. Сырые HTML,
HAR, заголовки, cookies и ответы авторизации не сохраняются.

## Обработка импортов и медиазапросов

На проверенной странице Shikimori разворачивает импорты, помечает каждый блок
комментарием с URL и только затем добавляет пользовательскую часть. Поэтому
браузерная вставка исходного CSS целиком — с `@media` перед `@import` — не повторяет
поведение сайта: часть импортов браузер может проигнорировать.

В [опубликованном исходнике обработчика Shikimori](https://github.com/shikimori/shikimori/blob/master/app/services/styles/compile.rb)
пользовательский CSS без `@media` оборачивается в
`@media only screen and (min-width: 1024px)`. При наличии `@media` дополнительная
обёртка не создаётся. В нашем CSS медиазапросы уже есть; действующая страница
подтвердила отсутствие такой общей обёртки. Sticky-меню от 1025px, фон от 1280px
и `content-visibility` от 1024px остаются на своих местах.

Локальная модель удаляет комментарии и поддерживаемые импорты, преобразует
HTTP(S)-ссылки в относительные к протоколу и воспроизводит указанное решение
об обёртке. Ошибочные старые `*/`, `}` и значения свойств намеренно не исправляются:
восстановление игнорируемых правил могло бы поменять дизайн.

**Полная эквивалентность будущей публикации не гарантируется.** Сервер также
[очищает CSS](https://github.com/shikimori/shikimori/blob/master/app/services/misc/sanitize_evil_css.rb)
и обрабатывает URL через Camo. Полная копия этих механизмов здесь не реализована,
а опубликованный исходник не является гарантией текущей серверной реализации.
Проверка CSSOM доказывает совместимость модели для текущего опубликованного
исходника, но не для любых новых конструкций в локальных изменениях.
Новые формы URL, экранирование, вложенные импорты, `@import` с media/layer/supports
требуют отдельного исследования. Произвольные изменённые и неподдерживаемые импорты
запрещены; разрешены только явно описанные выше полные переносы.

## Результаты

Каждый прогон создаёт `.preview/<время>/`:

- `index.html` — сравнение рядом «до/после» для каждой ширины;
- `*-before-top.png`, `*-after-top.png` — верх профиля;
- `*-before-details.png`, `*-after-details.png` — область избранного и достижений;
- `*-before-component.png`, `*-after-component.png` — отдельный снимок блока раскладки;
- `*-diff-*.png` — диагностическая разница пикселей;
- `report.json` — размеры, вычисленные стили, псевдоэлементы, изменения, ошибки
  загрузки изображений, хэши основы и исходников;
- снимки опубликованного, подготовленного и локального CSS для воспроизводимости.

Вся `.preview/`, `node_modules/` и локальное хранилище pnpm исключены из Git.
Для раскладки сравниваются все вычисленные свойства всех 458 текущих узлов.
В отчёт записываются их геометрия, хэши свойств и конкретные различия, а не десятки
мегабайт одинаковых значений до и после. Ключевые элементы сохраняют явные значения.
Снимки — области окна, а не всей длинной страницы. На узких экранах в области
избранного может не помещаться весь блок достижений; он также проверяется через DOM.
Каталоги, фильтры, hover/focus, комментарии и вид владельца пока не покрыты.
Это ограничение обычного профильного прогона. Режим `--component history --check-history`
проверяет реальную историю, hover/focus/active, ru/en и отдельные примеры для трёх
типов ссылок и вложенной подсказки. Английский вариант проверяется временным
атрибутом `data-locale`; настройки аккаунта не меняются. Отсутствующие реальные
ветки (например, ранобэ) явно отмечаются, а не выдаются за реальное покрытие.
`--check-layout` разрешён только для профиля, `--check-history` — только для истории.

История требует ровно семь локальных правил и одно помеченное совместимостное
объявление tooltip `content: ""`. Проверка оставшихся правил исключает только эти
ожидаемые определения, а не весь импорт постеров. Значение исходного content
постеров проверяется отдельно: при его изменении миграция не получает PASS.
При структурном FAIL состояния не запускаются, итоговый код всё равно 1.
Структурный аудит проверяет реальные правила CSSOM, их число, происхождение,
медиазапросы, каскад и отсутствие лишних копий в других листах. Проверка с намеренно
пропущенным правилом, включая повтор старой основы, описана в [аудите](layout-audit.md).

CSS-анимации ставятся на паузу в момент 0, переходы отключаются одинаково до и после.
Снимки используют `animations: 'allow'` для уже остановленных эффектов:
`'disabled'` дополнительно завершал конечные анимации и искажал сравнение.
Это помогает сравнивать геометрию, но отдельный обычный прогон нужен для оценки
движения. GIF/WebP, включая надпись TOP/TIERLIST и фон, **не замораживаются**:
разница пикселей не является автоматическим провалом теста. Возможны также
асинхронные изменения самой страницы и появление подсказок.

Мобильные ширины фиксируют существующее состояние, а не задают образец исправного
мобильного дизайна. Проверка Chromium не заменяет Firefox и настоящий телефон.
`report.json` сравнивает ключевые элементы, но не каждое свойство каждого узла.

Снимки и остановка CSS-анимаций реализованы средствами
[Playwright Library](https://playwright.dev/docs/library) и
[Screenshot API](https://playwright.dev/docs/api/class-page#page-screenshot).

## График активности

`--check-activity` разрешён только на профиле и требует локального q05. Аудит
проверяет 40 правил CSSOM Chromium (38 обычных и два варианта keyframes), сохраняя
сырой исходник с четырьмя префиксными вариантами keyframes. Допустимое переопределение
одинакового селектора из E-design остаётся в сравнении остальных правил; исключаются
только точные переносимые определения.

Отдельный проход графика сравнивает геометрию, все вычисленные свойства узлов
и псевдоэлементов в заданных позициях времени и при hover. Во время него снимается
общая принудительная CSS-пауза, а WAAPI задаёт одинаковые времена с сохранением
индивидуальных задержек. CSS pause на hover проверяется отдельно. Для отсутствующего
34-го столбца видимого x26 записывается пропуск, не PASS этого состояния. Снимки
графика и состояния находятся в `activity.html` и `activity.json` рядом с отчётом.
Проверка запасной `fluctuations` в тестовом DOM не эмулирует старые движки.
Подробности переноса и ограничения — [q05](q05-migration.md).

## Механизм постеров

`--check-posters` работает на профиле и проверяет десять правил CSS-club.
Новый блок ставится перед AUTO-sticky, поэтому дополнительно требуется полное
совпадение разобранного CSSOM с baseline, а не только отсутствие отличий геометрии.
Проверка q03 принимает локальный источник постеров только после проверки полного
снимка и прежнего `content: ""` без `!important`; остальные защиты сохранены.

Сравниваются постеры профиля и настоящая подсказка, публичная страница коллекций
с временно подставленной темой профиля, обычные/spoiler состояния и hover.
Censored, сочетания флагов, нестандартные переменные и ru/en дополнены явными
примерами с базовыми стилями реального сайта. Скрытый мобильный DOM подсказки
не считается проверкой видимого мобильного popup.

Сводка и снимки — `posters.html`, данные и ограничения — `posters.json`.
Подробности: [posters-migration.md](posters-migration.md). Firefox, реальные
устройства и авторизованный вид не покрываются этим прогоном.

## Фиксация версий E-design

Отдельный путь меняет только разрешённые пары master→commit из
`vendor/edesign-pins.json`, сохраняя число/порядок импортов и всё содержимое правил.
Сверяются SHA256 snapshot и свежего pinned-ответа, затем CSSOM snapshot и реального
скомпилированного блока. В предпросмотре заменяются только URL в метках основы.
При недоступном файле, чужом SHA, повреждённом снимке или несовпадении CSSOM — ERROR.
Этот путь не разрешает произвольную замену импортов и не совмещается с их удалением.
Проверка действует и после публикации pinned-ссылок. Подробности и ограничения —
[edesign-foundation.md](edesign-foundation.md).

### Наблюдаемые URL main1/main4

Для двух оставшихся источников манифест содержит конкретные `compiledUrlRewrites`.
Сверка привязана к индексу/хэшу правила и количеству настоящих URL-токенов;
допускается только ожидаемое раскрытие `/x/…` или наблюдаемый Camo-адрес того же
ресурса. После этого проверяется весь CSSOM. Кандидат не получает новые ресурсные URL:
foundation сохраняет опубликованные правила. Любое неизвестное отличие даёт ERROR.
Это не универсальная эмуляция санитайзера; детали — [аудит URL](edesign-url-audit.md).

## Прямой импорт своего модуля: локальный пилот

`css/imports.json` задаёт точную разрешённую замену источника E-design на
commit-URL этого репозитория. Порядок импортов и тело основы сохраняются;
проверяются SHA256 рабочего файла, snapshot и удалённого ответа, затем CSSOM.
Механизм разрешает только побайтно одинаковую копию, не произвольные изменения.

До push доступен явный локальный режим:

```powershell
node tools/preview/preview.mjs --css .preview/owned-import-work/candidate.css --local-imports --check-layout --widths 1440,390,360
node tools/preview/preview.mjs --css .preview/owned-import-work/candidate.css --local-imports --component history --widths 1440,390,360
```

Путь кандидата — временный пример из пилота, в Git он не входит. В этом режиме
проверяются локальный модуль и его содержимое в указанном Git-коммите, результат
помечается **LOCAL PASS**, `remoteSourcesVerified: false`. Это не готовность
к публикации. Без флага требуется успешный GET настоящего commit-URL и совпадение
хэша; при 404/ошибке/отличии нет локального fallback. Данный перенос источника
не совмещается с фиксацией версии или удалением других импортов за один запуск.
План, результаты и ограничения — [owned-import-pilot.md](owned-import-pilot.md).

## Точечный пилот радиуса main3

Пилот раннего радиуса main3: `--main3-radius-candidate <workspace.css>` работает
с `profile|history|catalog`, разрешает только удаление конкретного объявления и
требует прежнего опубликованного CSS. Подробности, рабочие команды и исправление
измерений auto-margin: [main3-radius-optimization.md](main3-radius-optimization.md).
После подключения URL из `css/main3-optimization.json` обычный запуск проверяет
эту точную версию без флага пилота; проверка байтов, remote SHA и реального
скомпилированного блока сохраняется. Другие изменения основы не разрешены.

## Точечный пилот оптимизации main1

`--main1-button-candidate <workspace.css>` разрешает только точное удаление
второго дублирующего блока `.b-link_button`, с проверкой прежних источников,
неизменных байтов и разницы CSSOM в одно правило. Работает только с текущим
профилем, без `--local-imports`, historical replay и других CSS-изменений.
Это не общий механизм изменения основы. При отсутствии реальных кнопок
вердикт **INCOMPLETE**, exit 2; исходный строгий FAIL сохраняется отдельно.
Команда, покрытие и ограничения: [main1-button-optimization.md](main1-button-optimization.md).

После подключения оптимизированной версии обычный запуск `--check-layout`
использует `css/main1-optimization.json`: проверяет старый эталон, точное удаление,
новый remote SHA и реальный скомпилированный блок. До публикации разрешена только
замена этого URL без других правок; после публикации проверяется весь новый CSSOM.
Известные URL-rewrite исключения сохраняют хэши правил; их индексы смещаются
только на доказанное удаление одного правила. При нулевом реальном покрытии
кнопок результат остаётся INCOMPLETE. Старый CLI-пилот предназначен для прежнего
baseline и не используется поверх уже подключённой оптимизации.
