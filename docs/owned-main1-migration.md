## URL и каскад

Используется прежний механизм `css/imports.json`; логика Playwright не менялась.
В реальном серверном CSS подтверждены два известных правила с четырьмя URL:
три адреса FontAwesome `/x/maxcdn…` раскрыты в прямые URL, одна картинка Google
обёрнута в наблюдаемый Camo-адрес. Индексы правил — 6 и 244 (с нуля).
Точные пары, количество и хэши правил уже закреплены в `vendor/edesign-pins.json`.

Исключения используются только для сравнения CSSOM, не для записи новых URL
в рабочий модуль. CSS-body опубликованной основы сохраняется; в кандидате
меняется только метка источника. Любое отличие вне утверждённых URL — ошибка.
Это не эмуляция всех преобразований Shikimori: новый серверный результат
собственного URL ещё предстоит проверить после публикации.

## Ограничения и продолжение

`remoteSourcesVerified: false`: LOCAL PASS проверяет модуль локально и в Git-коммите,
но не подтверждает доступность нового URL. Основной CSS пока не переключён
(SHA256 `c97752ed303bbc92b7d933b73292727202ddcc105b7b1904f32a423d1e172b36`).
Следующий шаг после отдельного разрешения — push нового модуля и манифеста,
обычный предпросмотр без `--local-imports`, затем переключение основного CSS
и повторный прогон. Публикация Shikimori требует своего разрешения и проверки
реально скомпилированного CSS, включая URL и иконки.

Каталог, редактор, меню во всех состояниях и прочие страницы отдельно не
проверялись в реальном DOM. Полный CSSOM подтверждает сохранение их правил,
но не заменяет визуальную проверку каждого компонента. Состояния истории отдельно
не запускались. Media-условия не менялись, дополнительные границы не прогонялись.
Firefox, авторизованный вид, реальные устройства и все форматы шрифтов не покрыты;
старые EOT/SVG и браузерно игнорируемые объявления не объявляются проверенными
по сериализации Chromium. Байты исходника сохранены полностью.

После main1 останется main4. Шрифты остаются внешними. Новая версия upstream
потребует отдельного сравнения: commit-URL не обновляется автоматически.
