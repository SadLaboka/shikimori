# Публикация CSS в Shikimori из Windows

Требования: Windows, PowerShell 7+, Git. Скрипт отправляет локальный файл;
Этот способ не зависит от видимости GitHub-репозитория. Публикация CSS не делает git push.
Команды ниже выполняются из корня репозитория.

Для уже настроенного проекта: [короткий порядок выпуска](release.md).
`-CompactDiff` сохраняет полный diff в `.preview/deploy/`, ограничивая вывод
40 строками/6000 символами. `-ExpectedCssSha256` проверяет соответствие ранее
проверенному CSS до чтения credentials и сети. Подтверждение, backup и
проверки аккаунта/конфликта/результата сохраняются. Без этих параметров
прежний интерактивный процесс остаётся доступен.

## Сначала настройка без секретов

Скопируйте `deploy.config.json` в `deploy.local.json` и заполните:

- `applicationName`: точное название зарегистрированного OAuth-приложения (User-Agent).
- `expectedNickname`: ожидаемый никнейм, сейчас SadLaboka.
- `expectedUserId`: числовой ID своего пользователя.
- `styleId`: ID существующего активного стиля, а не ID пользователя.
- `clientId`: публичный идентификатор приложения.
- `redirectUri`: полный зарегистрированный адрес перенаправления без query и fragment.
- `scopes`: минимальные разрешения, поддерживаемые приложением. Отдельный scope `styles`
  в документации метода не указан. Проверьте фактические права на экране согласия;
  пустая строка не гарантирует отсутствие прав по умолчанию.

ID стиля можно посмотреть в HTML формы редактора CSS: её `action` может иметь вид
`/api/v3/users/styles/<id>`. Запрос в Network при простом открытии редактора может
отсутствовать. Скрипт использует документированный `/api/styles/<id>`; чтение и
обновление собственного стиля через этот маршрут проверены. Ничего сохранять для поиска ID не требуется. Не копируйте
cookies, CSRF-токены, заголовки Authorization или весь запрос в чат.

Секреты нельзя записывать в конфигурацию, CSS, Git, команды терминала или чат.
`deploy.local.json` игнорируется Git, но всё равно предназначен только для несекретных значений.

## Отдельная первоначальная авторизация

Этот этап обращается к OAuth и требует отдельного осознанного запуска:

```powershell
pwsh -NoProfile -File .\scripts\deploy.ps1 -Authorize -ConfigPath .\deploy.local.json
```

Скрипт выводит ссылку авторизации, которую нужно открыть самостоятельно. После согласия
скопируйте полный конечный адрес из браузера в скрытый ввод терминала. Проверяется state
и совпадение адреса перенаправления. Для зарегистрированного localhost callback страница
может не открыться: скрипт не запускает локальный HTTP-сервер, нужен адрес из адресной строки.
Этот режим рассчитан на redirect с параметрами `code` и `state`, а не на OOB-страницу с одним кодом.
Затем введите client secret скрыто и подтвердите `AUTHORIZE` для обмена кода на токены.
Профиль при этом не изменяется. Не запускайте под отладчиком, с HTTP-трассировкой или
записью сетевого трафика. Если включено принудительное корпоративное логирование,
сначала уточните его политику; скрипт не может управлять внешними средствами записи.

Токены и client secret хранятся одним DPAPI-зашифрованным файлом:
`%LOCALAPPDATA%\ShikimoriCssDeploy\credentials.dpapi`.
Он привязан к пользователю Windows; это не переносимая резервная копия.
Секреты расшифровываются только в памяти процесса; скрипт не выводит их значения.

## Проверка и публикация

```powershell
# Без сети, без credentials: сравнение с ранее сохранённым исходным CSS.
pwsh -NoProfile -File .\scripts\deploy.ps1 -DryRun -Baseline C:\path\previous.css

# Только GET: проверить аккаунт, получить стиль, сохранить backup, показать diff.
pwsh -NoProfile -File .\scripts\deploy.ps1 -DryRun -ConfigPath .\deploy.local.json

# Тот же процесс, затем ручное подтверждение и один PATCH.
pwsh -NoProfile -File .\scripts\deploy.ps1 -Publish -ConfigPath .\deploy.local.json
```

Без переключателя режим также dry-run. Git diff показывает `-` для удалённых строк,
`+` для добавленных. Тело публикации берётся из того же снимка, что и diff.
Пустой CSS запрещён. При совпадении CSS PATCH не выполняется.
Резервная копия обязательна: ошибка её сохранения останавливает публикацию.

После просмотра diff нужно ввести точную фразу `PUBLISH SadLaboka <styleId>`.
Скрипт повторно читает стиль и прекращает работу при изменении CSS или updated_at.
Это не атомарная блокировка: серверный If-Match для этого метода не документирован.
При ошибке PATCH повторной отправки нет; выполняется GET для выяснения результата.
Успех означает совпадение сохранённого `css`, а не проверку внешнего вида в браузере.

## Обновление токенов и восстановление CSS

Dry-run и публикация не обновляют токены автоматически. Для просроченной пары:

```powershell
pwsh -NoProfile -File .\scripts\deploy.ps1 -RefreshCredentials -ConfigPath .\deploy.local.json
```

После подтверждения `REFRESH` скрипт сохраняет новую пару токенов атомарной заменой
локального файла. Если ответ token endpoint потерян или запись не удалась, не делайте
бесконечных повторов: может потребоваться новая авторизация.

Backups хранятся в `%LOCALAPPDATA%\ShikimoriCssDeploy\backups`:
исходный `.css` и метаданные `.json` с ID, временем и SHA256, без токенов и HTTP-заголовков.
Для отката передайте выбранную копию через `-CssPath`: сначала dry-run, затем `-Publish`
с обычным подтверждением. Автоматического отката нет.

Внешние импорты могут измениться независимо от CSS. Исходная резервная копия не фиксирует
версии внешней темы. Серверная компиляция может менять URL и обрабатывать импорты;
поэтому скрипт сравнивает `css`, а не `compiled_css`. Опубликованный CSS виден посетителям
профиля и не должен содержать секретных ссылок.

## Локальные тесты

```powershell
pwsh -NoProfile -File .\tests\deploy.tests.ps1
```

Тесты используют подставной API и временные файлы. Реальные credentials и профиль
не используются. Проверяются dry-run, подтверждение, владелец, конфликт изменений,
таймаут, сверка результата, резервирование и неизменность просмотренного снимка.

## Особенности Windows и проверок

Актуальный путь — `scripts/deploy.ps1`; старого корневого `deploy.ps1` больше нет.
Команды выполняются из корня репозитория.

- PowerShell 7+ обязателен. Если `pwsh` отсутствует в PATH, найди полный путь
  установленного исполняемого файла. Предупреждение PSReadLine само по себе
  не означает ошибку авторизации.
- `ConvertFrom-Json` в новых версиях PowerShell может возвращать дату объектом
  `DateTime`, а не строкой. В скрипте этот случай уже обработан и покрыт тестом.

Тесты deploy используют подставной API и искусственные секреты DPAPI. Доступ к
профилю пользователя Windows может быть недоступен из песочницы; проверку DPAPI
нельзя подменять реальными токенами. Не выводить сырые HTTP-исключения, заголовки
или расшифрованные credentials. Сравнивать и резервировать исходное поле `css`,
не `compiled_css`; отправлять тот же снимок, который показан в diff.

Push и PATCH — отдельные разрешения на согласованный пакет. Уже предоставленное
разрешение повторно не запрашивается и не распространяется на новые изменения.
