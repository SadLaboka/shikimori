# Автосмена схем через GitHub Actions

Workflow [Rotate Shikimori schemes](../.github/workflows/rotate-schemes.yml) работает
на серверах GitHub, независимо от компьютера и Firefox. По умолчанию он выключен:
без переменной `SHIKIMORI_ROTATION_ENABLED=true` расписание ничего не публикует.
Подготовка файлов не означает, что доступ уже настроен или автосмена включена.

## Поведение

- Расписание: на 7-й и 37-й минуте каждого часа. Это примерно раз в полчаса:
  GitHub может задержать или пропустить запуск. После 60 дней без активности
  публичного репозитория GitHub отключает расписание.
- Каталог общий с расширением: `extensions/firefox/catalog.mjs`, функции
  `recognize`, `nextSchemeId`, `schemeCss` и явный `CYCLE_ORDER`.
  Сейчас: Основная → Emerald & Scarlet → Gold & Jade → Основная.
- Перед каждым переключением читаются аккаунт и сохранённый CSS.
  Неизвестный CSS и неправильный владелец останавливают запись.
- Распознавание известных блоков учитывает LF/CRLF и пробелы по краям, которые
  появляются при сохранении через настройки сайта. Изменение правил или адресов
  импортов по-прежнему останавливает автоматику. Backup, проверка конфликтов
  и SHA256 операции используют точный сохранённый текст.
- После любого ручного изменения стиля выдерживается минимум 30 минут
  по серверному `updated_at`. Если следующий запуск придёт раньше,
  он пропустит переключение; интервал может получиться больше получаса.
  Повторное применение идентичного CSS учитывается, только если сайт изменил `updated_at`.
  Для подтверждённых автоматических переключений учитывается получасовой интервал:
  небольшая разница во времени запуска не пропускает целый следующий цикл.
- Проверяется исходник на этапе подготовки и ещё раз непосредственно перед PATCH.
  Автосмена использует `scripts/deploy.ps1`: SHA256, diff, backup и сверка
  сохранённого `css`. CSS совпадает с блоком, который отправляет расширение.
- Исходный CSS, кандидат и метаданные загружаются в артефакт GitHub **до PATCH**;
  срок хранения 14 дней. Артефакт содержит только публичное оформление, без credentials.
- Незавершённая запись сохраняется в переменной состояния. Следующий запуск
  только проверит её результат. При несовпадении автоматика останется остановленной;
  повторной отправки и автоматического отката нет.
- Открытые страницы не перезагружаются. Новый CSS виден после перехода/обновления.

Расширение продолжает работать без обновления. Его меню может попросить заново
прочитать состояние, если Actions уже изменил CSS. Общей блокировки между
Firefox и GitHub нет: узкое окно между последним GET и PATCH остаётся,
поскольку API Shikimori не документирует условную атомарную запись.
Одновременные запуски самого workflow сериализованы через `concurrency`.
Для строгой общей очереди понадобится отдельный сервис и обновление расширения.

## Первоначальная настройка

Push, OAuth, загрузка секретов, refresh и включение публикации — отдельные действия.
Команды ниже — инструкция; подготовка реализации их не выполняет.

1. После проверки и отдельного разрешения отправить workflow и скрипты в `main`.
2. Создать **отдельное OAuth-приложение Shikimori для автосмены**. Не использовать
   пару токенов локального deploy: облачный refresh заменяет её, локальная копия
   становится устаревшей. Скопировать `deploy.config.json` в игнорируемый
   `rotation.local.json`, указать точное имя приложения, его `clientId`, redirect,
   `expectedNickname=SadLaboka`, `expectedUserId=1408017`, `styleId=1343722`.
   Client secret в конфигурацию не записывать.
3. Отдельно авторизовать профиль автосмены:

   ```powershell
   pwsh -NoProfile -File scripts/deploy.ps1 -Authorize -CredentialProfile rotation -ConfigPath rotation.local.json
   ```

   Скрытый ввод и подтверждение аналогичны [обычному OAuth](deployment.md).
   Credentials находятся в DPAPI-профиле
   `%LOCALAPPDATA%/ShikimoriCssDeploy/rotation/credentials.dpapi`.
   Облачный refresh не обновляет этот локальный файл. Не загружать его повторно
   после начала облачной работы без отдельного восстановления авторизации.
4. Создать fine-grained GitHub PAT только для `SadLaboka/shikimori`, права
   **Secrets: read/write**, **Variables: read/write**, стандартное чтение metadata.
   Записать его через защищённую форму Settings → Secrets and variables → Actions
   как repository secret `SHIKIMORI_ROTATION_ADMIN_TOKEN`. Не отправлять в чат.
   Этот токен нужен для сохранения новой пары OAuth и журнала между запусками;
   стандартный `GITHUB_TOKEN` не заменяет права управления secrets/variables.
   Следить за сроком PAT: после его истечения автоматика остановится.
5. При настроенном входе `gh` отдельно загрузить credentials:

   ```powershell
   pwsh -NoProfile -File scripts/upload-rotation-credentials.ps1 -Upload -ConfigPath rotation.local.json
   ```

   После `UPLOAD ROTATION` скрипт передаёт JSON в стандартный ввод `gh secret set`;
   GitHub CLI шифрует его перед отправкой. Секретов в аргументах и выводе нет.
   Создаётся secret `SHIKIMORI_ROTATION_CREDENTIALS` и variable
   `SHIKIMORI_ROTATION_APPLICATION_NAME`. Расписание не включается, журнал не сбрасывается.
6. Через Settings → Secrets and variables → Actions → Variables создать:

   | Variable | Первоначальное значение |
   | --- | --- |
   | `SHIKIMORI_ROTATION_ENABLED` | `false` |
   | `SHIKIMORI_ROTATION_STATE` | `{"version":1}` |

   Состояние создаётся **один раз**. Автоматика намеренно не создаёт его заново,
   если оно удалено: иначе потеряется защита от повторения незавершённой записи.
7. Запустить Actions → Rotate Shikimori schemes → Run workflow → **dry-run**, ветка
   `main`. К API Shikimori этот режим выполняет только GET, не обновляет OAuth,
   secrets или state и не публикует CSS; готовый план сохраняется артефактом GitHub.
   Если схема менялась менее получаса назад, он сообщает ожидание.
   В готовом плане проверить diff, SHA256 и артефакт. Если токен скоро истечёт,
   dry-run остановится: сначала восстановить отдельную авторизацию.
8. После отдельного разрешения на постоянную автопубликацию установить
   `SHIKIMORI_ROTATION_ENABLED=true`. Режим **publish** позволяет выполнить
   ту же проверенную операцию вручную; выдержка 30 минут сохраняется.
   Первое живое сохранение ещё требует проверки реального оформления и импортов.

Включение расписания разрешает будущие публикации схем каталога и необходимый
refresh OAuth. Оно не разрешает автоматически добавлять непроверенные схемы,
публиковать произвольный CSS или выпускать расширение.

## Данные и восстановление

### Схема не меняется или появились ошибки импорта

Сначала прочитать ошибку этапа `Prepare and inspect the next scheme`. Сообщение
«Неизвестный CSS» относится к исходному тексту CSS, а не к доступности импортов.
Сохранение через редактор сайта может изменить только переводы строк; каталог
учитывает это начиная с Firefox 0.3.8. Для Actions нужен соответствующий код в `main`.

`failed_imports` означает, что Shikimori сохранил CSS, но не смог скачать указанные
зависимости для сборки оформления. HTTP 200 при прямом запросе с компьютера
не доказывает доступность файла с сервера Shikimori. В опубликованном
[исходнике загрузчика Shikimori](https://github.com/shikimori/shikimori/blob/master/app/services/styles/download.rb)
результат загрузки кэшируется на 8 часов, включая пустой ответ после HTTP-ошибки;
работа текущего сервера может отличаться от архивного исходника.

В каталоге 0.3.8 `IMPORT_MIRRORS` заменяет только два согласованных адреса:
`2d919a0…/css/base/main_code_3.css` и
`178429b…/css/themes/emerald-scarlet/styles.css`. Зеркало jsDelivr закреплено
на тех же полных commit SHA; контрольные суммы исходных файлов сохранены рядом
с адресами. Содержимое CSS, порядок импортов и адреса изображений не меняются.
Распознаются как прежние raw-блоки, так и новые блоки с зеркалами.

Не повторять PATCH автоматически и не менять закреплённые URL ради обхода ошибки.
Расширение показывает неполную загрузку при открытии меню и при повторном выборе
той же схемы. Замена источника, сброс кэша сайта и повторная публикация требуют
отдельно выбранного способа восстановления. Совпадение исходного `css` с кандидатом
подтверждает сохранение текста, но не полноту `compiled_css`.

### Журнал и credentials

В `SHIKIMORI_ROTATION_CREDENTIALS` хранится один JSON с `clientId`, `clientSecret`,
`accessToken`, `refreshToken`, `expiresAt`. Перед сетевыми операциями значения
токенов маскируются по отдельности. Временный plaintext-файл нужен только deploy
на одноразовом runner и удаляется завершающим шагом; в артефакты он не входит.
DPAPI в облаке не используется. Секреты не записываются в Git и не выводятся в журнал.

В `SHIKIMORI_ROTATION_STATE` находятся только версия формата, контрольная сумма
набора credentials, `refreshPending`, последняя подтверждённая автосмена и
`pending` с SHA256 исходника/кандидата, временем и ID артефакта backup.
State читается через API заново; `vars`-снимок workflow для него не используется.
Проверка суммы credentials отклоняет запуск со старым секретом, полученным при
постановке в очередь до обновления OAuth. Следующий свежий запуск получит новую пару.

Перед refresh сохраняется `refreshPending=true`, затем выполняется один обмен,
новая пара сохраняется одним секретом, и только потом снимается отметка.
Потерянный ответ OAuth или ошибка сохранения оставляют автоматику остановленной.
Бесконечно повторять refresh старой парой нельзя.

При сбое:

1. Установить `SHIKIMORI_ROTATION_ENABLED=false`, дождаться завершения текущего job.
   Выключение предотвращает новые записи; уже начатый PATCH отменить этим нельзя.
2. Для `pending` запустить **reconcile**: только проверка результата, без новой
   записи и refresh. Если серверный CSS равен кандидату, журнал закроется.
   При истёкшем токене нужна отдельная проверка/восстановление доступа.
3. Если CSS остался прежним или был изменён вручную, сохранить state и backup,
   проверить текущий CSS. Только после выяснения результата отдельно удалить поле
   `pending`, сохранив остальные поля. Не сбрасывать весь журнал ради повтора job.
4. При `refreshPending` или замене credentials отдельно восстановить авторизацию
   профиля `rotation` и загрузить **новую** пару. После проверки убрать только
   `refreshPending` и `credentialsHash`, сохранив `pending` и `lastAuto`.
   Не выполнять старой парой повторный refresh. Затем dry-run/reconcile.
5. Возобновление расписания — только после устранения причины. Для отката CSS
   использовать backup и обычный `scripts/deploy.ps1` с отдельным разрешением.

Не загружать credentials в комментарии, issues, артефакты и логи. Не включать
`GH_DEBUG`, HTTP tracing или запись OAuth-запросов.

## Добавление готовой схемы

Создание и визуальная проверка палитры выполняются по навыку
[shikimori-color-schemes](../.agents/skills/shikimori-color-schemes/SKILL.md).
Для подключения к системе использовать
[shikimori-scheme-rotation](../.agents/skills/shikimori-scheme-rotation/SKILL.md).

Каталог общий: добавить новую схему с проверенным SHA256, неизменяемым commit-URL
и явным местом в `CYCLE_ORDER`. Сохранить распознавание прежних вариантов.
Отдельного списка схем в Actions нет. При добавлении схемы проверить полный круг
и переход с каждой ранее установленной схемы. Само появление папки в `css/themes`
не включает её в автосмену.

Изменение каталога затрагивает и будущую сборку расширения, но установленный XPI
получит его только после отдельного выпуска. Если Actions включить раньше,
старый XPI может не распознать новую схему. Сначала согласовать и выпустить
совместимое расширение, затем разрешённо обновить каталог активной автосмены.
Для этого можно временно остановить расписание; не менять его состояние без разрешения.

Проверки изменённой логики:

```powershell
node --test tests/rotation.test.mjs tests/firefox-extension.test.mjs tests/firefox-avatar.test.mjs
pwsh -NoProfile -File tests/deploy.tests.ps1
pwsh -NoProfile -File tests/rotation-deploy.tests.ps1
pwsh -NoProfile -File tests/rotation-upload.tests.ps1
node scripts/build-css.mjs --check
node scripts/build-emerald-scarlet.mjs --check
node scripts/build-gold-jade.mjs --check
git diff --check
```

Для новой схемы добавить её собственную сборку `--check` и проверки в workflow;
не считать перечисленные три сборки покрытием будущей схемы. Тесты используют
подставной API и искусственные credentials. Они не доказывают настройку GitHub,
живую авторизацию, запуск расписания и компиляцию CSS на Shikimori.
