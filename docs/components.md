# Пользовательские компоненты CSS

Редактируемые исходники — `css/components/`; `styles_optimized.css` остаётся
собранным файлом для прежнего Playwright и deploy. Внешняя основа `css/base/`
не разбивалась повторно. Посторонний `docs/firefox-reflection.md` не изменялся.

## Разделение

`css/components.json` перечисляет 22 части в прежнем порядке. Сборка читает
список явно, не сортирует файлы и не добавляет разделители, заголовки или пробелы.

| Части | Содержимое |
| --- | --- |
| 00–01 | Механизм постеров, исходные импорты основы и шрифтов, sticky AUTO |
| 02–04 | График активности, история с совместимостью tooltip, раскладка профиля |
| 05–07 | Палитра и фон, полосы прокрутки, шапка с отражениями |
| 08–13 | Статус/ник, заголовки, TOP, вход/аватар, содержимое профиля, прогресс |
| 14–17 | Поиск, комментарии, достижения/франшизы, избранное |
| 18–20 | Поздние правила отрисовки/графика, фильтры, скрытие подсказок |
| 21-mobile | Вся готовая мобильная адаптация и prefers-reduced-motion, в конце |

Некоторые компоненты связаны: график 02 имеет поздние overrides в 18; мобильные
правила 21 переопределяют предыдущие части. Не объединяй такие фрагменты через
перестановку: исходный порядок — часть оформления. Сохраняются глобальные
селекторы, `@media`, `@supports`, keyframes, псевдоэлементы и авторство.

## Почему простая склейка

Сетевые `@import` компонентов изменили бы обработку пользовательской части
Shikimori: сервер отдельно извлекает импорты и формирует foundation, а поздние
правила должны сохранить прежнее место. В исходнике также есть старые ошибки
синтаксиса. Разбор/пересериализация каждого фрагмента может изменить восстановление
парсером. Поэтому выбран минимальный локальный способ без новых зависимостей:
только `Buffer.concat` в заданном порядке, без минификации и оптимизации.
Фрагменты не предназначены для самостоятельного подключения через `@import`.
Действующие сетевые импорты не изменены и новые не добавлены.

## Работа с изменениями

```powershell
# 1. Правка нужного компонента, затем кандидат без изменения основного файла
node scripts/build-css.mjs --write --output .preview/candidate.css

# 2. Целевой предпросмотр, например профиль
node tools/preview/preview.mjs --css .preview/candidate.css --check-layout --widths 1440,390,360

# 3. После проверки: собрать тот же снимок в файл публикации и сверить SHA256
node scripts/build-css.mjs --write
node scripts/build-css.mjs --check

# Тесты склейки: без сети, браузера и credentials
node --test tests/build-css.test.mjs
```

Без параметров сборка работает как `--check`: устаревший итоговый файл вызывает
ошибку, он не перезаписывается автоматически. Проверка не является CSS-линтером
или визуальным PASS. Для CSS-пропусков и регрессий по-прежнему нужны существующие
CSSOM/Playwright-проверки. При копировании тех же байтов повторять их не требуется.
Генерируемый файл хранится в Git вместе с компонентами: штатная публикация
по-прежнему отправляет готовый проверенный CSS, не выполняя сборку в процессе PATCH.

Порядок файлов и состав manifest изменяются осознанно; дубли, выход за каталог,
недостающий/неперечисленный файл и устаревший результат отклоняются. Кандидаты разрешены только
в `.preview/`, постоянный выход — только `styles_optimized.css`.
В `.gitattributes` для компонентов и итогового файла закреплены LF, чтобы
Windows checkout не нарушал побайтное равенство разными окончаниями строк.

## Инвариант первого разделения, 26 октября 2026

До разделения и после сборки: **74 570 байт**, SHA256
`32e8023cc1dfef2cdd2c89a8a0da7f01633731a282de6c559f1ffd54540f8272`.
Все байты мобильной версии из коммита `ecbfa1f` сохранены. Не менялись изображения,
анимации, значения/порядок правил, импорты, legacy-синтаксис и итоговый файл.
В том числе сохранены старые концевые пробелы и пустые строки между частями:
предупреждения whitespace при первом добавлении частей не исправлялись ценой
изменения байтов. Проверено также равенство склейки staged-файлов итоговому CSS.
Публикация и push в этом этапе не выполняются; внешний вид на сайте от самой
организации исходников не меняется. Ускорение загрузки/отрисовки не обещается.

- Тесты склейки: 2/2. Проверены UTF-8, смешанные окончания строк, порядок,
  дубли/пропуски, неперечисленные CSS-файлы, stale output и выход за рабочие пути.
- Существующие тесты предпросмотра: 50/50; после изменения изоляции скриптов
  дополнительно пройдены 4 теста маршрутизации/каталога.
- Профиль, история и каталог: 1440/390/360, строгие инварианты PASS, полный CSSOM
  совпадает с опубликованным, изменений измеряемых стилей и геометрии нет.
  Итоговый целевой статус существующего инструмента называется LOCAL RADIUS PASS
  из-за активного main3-манифеста; это не новый перенос радиуса.
- Состояния ru/en истории и фильтров проверены на трёх ширинах, отличий нет.
  Скриншоты до/после сохранены, отдельно визуально не просматривались: вывод об
  эквивалентности опирается на точные байты, CSSOM и вычисленные стили. GIF/WebP
  продолжают менять кадры; диагностический pixel diff не равен регрессии.
