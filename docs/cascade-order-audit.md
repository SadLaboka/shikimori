# Аудит перестановки раскладки CSS-club и постеров

## Решение

Для проверенных версий стилей изменение порядка можно принять. Восстанавливать
старое положение блока или вводить сборщик CSS не требуется. Следующий перенос
этим решением не разрешается и не выполнялся.

Вывод основан на разборе всех пересечённых правил, а не только на снимках профиля:
не найдено ни одной пары объявлений, у которой перестановка меняет победителя.

## Что именно пересёк перенесённый блок

В реально скомпилированном CSS десять правил раскладки переместились через:

- десять правил `custom_posters.min.css`;
- два правила AUTO-sticky: `.l-top_menu-v2` и `.l-top_menu-v2 .active .submenu`.

Последние два находятся перед локальным блоком после обработки импортов Shikimori.
Таким образом, прежнее описание только про импорт постеров было неполным.
Индекс первого правила в развёрнутом CSSOM изменился с 2558 на 2570.
Все остальные правила сохранили содержимое и взаимный порядок; наборы и порядок
десяти правил раскладки также совпали. Псевдоэлементы не потеряны.

Проанализирован именно CSS постеров из действующего `style#custom_css`, а не
возможная другая версия по внешнему URL. Хэш наблюдённого блока с его пробелами:
`b9cb15dc2d70c77ff9bad7cfce620007c475a60041210dacfe78b3fa9f841399`.
Наблюдённая копия и полный разбор хранятся в игнорируемой `.preview/`.

## Пересечения каскада

Во всех трёх рассматриваемых блоках объявления обычные, без `!important`,
без `@layer` и `@scope`. Раскладка действует от 768px, постеры не ограничены
медиазапросом, AUTO-sticky действует от 1025px.

| Пересечение | Результат |
| --- | --- |
| `width`: колонки 100%/77%/23% и ссылка постера подсказки 160px | Специфичность раскладки `(1,3,0)`–`(1,5,0)`, ссылки подсказки — `(0,2,1)`. Даже при совпадении на одном узле выигрывает раскладка при обоих порядках. |
| `position`: `.c-right { position: static }` и ссылка подсказки `relative` | Приоритет у раскладки по ID; на реальном DOM это разные узлы. |
| `position: static` у изображения коллекции | Значение совпадает; селектор раскладки также имеет более высокий приоритет. |
| `position: absolute` у `::before` постеров | Это псевдоэлемент, а раскладка задаёт положение обычного элемента. Такие объявления не конкурируют за одно свойство одного объекта. |
| `position: sticky` меню и `position: static` колонки | На реальной странице узлы не совпадают; при искусственном совмещении классов ID раскладки сохраняет её приоритет. |
| `overflow-y`: `hidden` раскладки и `auto` активного подменю | Учтено разворачивание `overflow` в две оси. Специфичность раскладки `(1,4,0)` выше `(0,3,0)` у sticky-подменю. |
| Hover и `.is-censored`/`.is-spoilers` | Меняют `filter`/переход у `::before` постеров. Раскладка не задаёт эти свойства и псевдоэлементы. |
| Фон, `opacity`, `aspect-ratio`, скругления постеров | Раскладка не определяет эти свойства и используемые ими CSS-переменные. |
| Отступы, `float`, переключение x26/x34 | В импорте постеров для них нет конкурирующих объявлений. |

В специфичности сначала сравнивается число ID, затем классы/псевдоклассы,
затем типы/псевдоэлементы: [Selectors Level 4](https://www.w3.org/TR/selectors-4/#specificity-rules).
Применённый подсчёт намеренно принимает только наблюдённые простые селекторы;
неподдерживаемая новая конструкция вызывает ошибку аудита.

Всего найдено 12 пар пересекающихся объявлений с учётом селекторных списков:
две относятся к разным объектам «элемент/псевдоэлемент», десять — к обычным
элементам. Для всех десяти приоритет определяется раньше, чем очередь правил.
В исходном DOM профиля одновременных совпадений этих пар на одном узле нет.

## Проверка браузером

```powershell
node .\tools\preview\audit-order.mjs `
  --historical-compiled .preview/layout-audit-input/historical-compiled.css
```

Нужен реальный сохранённый CSS до переноса. Скрипт проверяет, что разница CSSOM
ограничена известной перестановкой, и прекращает аудит при других изменениях.
Он не пересобирает рабочий CSS, не редактирует основной файл и не публикует стиль.

В изолированном Chromium на одном DOM сравнивались старый и текущий порядок.
Ширины: **1440, 390, 360, 767, 768, 1024, 1025px**. Дополнительные четыре ширины
проверяют включение медиазапросов раскладки и AUTO-sticky.

- 28 сравнений реального профиля: обычное состояние, hover, focus, удержание
  кнопки мыши (`:active`). Подсказки избранного действительно появились и также
  попали в проверку. Проверялось до 534 узлов.
- 49 сравнений явно искусственного тестового DOM: обычная, цензурированная,
  спойлерная и совмещённая карточки; hover по ним, focus/active ссылки; активное
  и неактивное подменю. Дополнительно совмещены роли tooltip-ссылки и колонки,
  чтобы проверить приоритет даже при гипотетическом совпадении селекторов.
- На каждом узле проверены геометрия и 26 связанных со взаимодействием/отрисовкой
  свойств обычного элемента, `::before` и `::after`. Снимки обеих версий сохранены.

**Результат: 77 сравнений, 0 различий проверенных свойств и геометрии.**
Существующие восемь тестов предпросмотра также прошли. Основной CSS сохранил
прежний SHA256; отправок CSS и git push не было.

В первом прогоне задержанное закрытие tooltip после resize дало ложное отличие.
Исправлено ожидание завершения прошлого состояния и подтверждение стабильности
двумя последовательными измерениями. Скрытые узлы без прямоугольника больше не
получают ложные координаты из текущего scrollY. Повторный прогон прошёл полностью.

Локальный отчёт: `.preview/order-audit-2026-10-24T19-36-42-443Z/index.html`.
Эти файлы не входят в Git; в другом окружении аудит нужно повторить.

## Ограничения и следующий кандидат

Решение относится к этому набору правил. Новые ID, `!important`, каскадные слои
или новые свойства в обновлённом импорте потребуют повторного аудита. Firefox,
настоящие телефоны, все страницы и движение анимаций отдельно не проверялись.
CSS-анимации остановлены одинаково; WebP/GIF продолжают менять кадры. Схематичные
тестовые карточки не выдаются за проверку настоящей страницы коллекций.

Следующий кандидат — **`q03_history_bookmarks.css`**: семь правил маркировки
«Аниме / Манга / Ранобэ» на `.history-page`, включая английские подписи. Это
небольшой самостоятельный блок без изображений и анимаций. При согласовании
понадобятся проверка каскада всех пересечённых импортов и отдельная страница истории:
три типа ссылок, русский/английский интерфейс, три основных ширины и псевдоэлементы.
Сейчас его импорт и правила не изменены, перенос не начат.
