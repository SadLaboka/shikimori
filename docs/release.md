# Короткий порядок push и публикации

Push и публикация требуют отдельных разрешений на конкретный пакет.
Этот порядок не разрешает новые изменения дизайна, OAuth или refresh.
При обычном выпуске читай этот файл, а не весь deployment.md, Skills и старые отчёты.
Подробности и устранение сбоев — [deployment.md](deployment.md).

## Объём работы

- **Quick:** документация, статический анализ, небольшие операции Git и выпуск
  уже проверенных байтов. Браузер не нужен; необходимые проверки выпуска ниже сохраняются.
- **Standard:** обычные изменения CSS. Синтаксис, затронутые компоненты,
  состояния, ширины и визуальная проверка по design Skill.
- **Full:** миграции импортов, основа/каскад и логика инструментов проверки.
  Все обязательные проверки эквивалентности и безопасности затронутого пути,
  тесты инструментов и отрицательный контроль новой миграции. Это не запуск
  всех исторических сценариев, не относящихся к изменению.

Режим выбирается по изменению, не по желаемой скорости. Quick не превращает
непроверенный CSS в проверенный. Разрешение push/публикации не расширяет покрытие.

## Перед действием

1. Один раз проверь `git status --short`, состав пакета и сохранённый отчёт
   текущего кандидата. Сверь его `localHash` с SHA256 файла; для модулей — также
   проверенные хэши и закреплённые URL. Старый PASS не подходит другим байтам.
   `node scripts/build-css.mjs --check` подтверждает, что компоненты соответствуют
   итоговому CSS; не пересобирай незаметно другой снимок во время публикации.
   Условия переиспользования: тот же компонент/реальный DOM, состояния, ширины,
   браузер и логика проверки; неизменившиеся источники импортов и их порядок.
   Для подвижного внешнего URL одного хэша локального CSS недостаточно:
   при отсутствии актуального свидетельства проверь источник. Сводка старого
   PASS без этих условий не заменяет отчёт текущего кандидата.
2. Если код/байты и условия не менялись, не повторяй тесты, состояния Playwright,
   все скриншоты или статический аудит только из-за слова «публикуй»/«пуш».
   Неполное покрытие остаётся неполным. При изменениях повтори затронутые проверки.
3. Не переписывай инструменты во время выпуска без конкретной необходимости.
   При новой версии основы сначала обеспечь её строгую проверку: разрешение
   публикации не заменяет проверку содержимого нового commit-URL.

## Push

Проверь diff новых изменений и staged-состав; добавляй файлы явно.
Отдельные смысловые коммиты сохрани. Если коммиты уже готовы, не пересоздавай их.
Push выполняй один раз после подготовки пакета; проверка результата команды
достаточна, повторные fetch/log/ls-remote без ошибки не нужны.

Если новый commit-URL необходим для публикации, сначала отдельный коммит модуля
и push, затем проверка удалённого хэша, подключение URL и публикация.
Остальные коммиты пакета можно отправить одним последующим push.
При обычной правке пользовательского CSS публикация сама по себе push не требует.

## Публикация проверенного снимка

```powershell
pwsh -NoProfile -File scripts/deploy.ps1 -Publish -ConfigPath deploy.local.json -CompactDiff -ExpectedCssSha256 <SHA256_из_проверки>
```

Один процесс до подтверждения проверяет аккаунт/владельца, сохраняет backup
и показывает предварительный diff; затем ждёт `PUBLISH …`. Это безопасный этап
просмотра до PATCH. Не запускай дополнительно идентичный `-DryRun` по привычке.
Отдельный `-DryRun` нужен по запросу, без разрешения публикации или если просмотр
и отправка намеренно разделены. Режим без сети: `-DryRun -Baseline <saved.css>`.

`-ExpectedCssSha256` останавливает изменившийся CSS до credentials и сети.
Он не заменяет разрешение пользователя и подтверждение в скрипте.
`-CompactDiff` ограничивает только вывод (40 строк, 6000 символов): полный diff
остаётся в игнорируемой `.preview/deploy/`. Если вывод сокращён, прочитай полный
diff перед подтверждением; не считай сводку полноценной проверкой изменений.

Скрипт повторно читает серверный стиль перед PATCH и сверяет `css` после него.
Повторный PATCH после ошибки запрещён без выяснения результата. Refresh отдельно.
Не читай и не печатай credentials; не используй HTTP-трассировку или транскрипцию.
Для диагностики добавь `-Timings`: выводит только миллисекунды total, diff,
confirmation, api-throttle и api-network (только выполненные этапы).
Confirmation — время ожидания ввода, network — запрос без обязательной паузы;
total включает запуск тела скрипта, но не старт процесса PowerShell/работу модели.
Таймеры не меняют число запросов, подтверждения и обработку ошибок PATCH.

## После

- Серверный исходный `css` уже сверяет deploy; дополнительный идентичный GET
  без причины не нужен.
- Для нового импорта/версии, URL/media обработки нужна проверка реального
  `style#custom_css` и CSSOM после публикации. Обычно достаточно одной ширины,
  если состояния и мобильные ширины тех же байтов проверены до публикации;
  новые расхождения требуют повторить затронутые проверки.
- Для обычных локальных правил выбирай проверку по риску; не запускай полный
  миграционный прогон после каждого push. Push документации браузера не требует.
- Итог: выполненные действия, результат, существенные ограничения и ссылка
  на текущий отчёт. Не переписывай весь журнал проверок в чат и документацию.
