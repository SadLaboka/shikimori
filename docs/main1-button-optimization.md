# Первый кандидат оптимизации main1

Подготовлен локальный пилот удаления второго блока `.b-link_button` из
`css/base/main_code_1.css` (четыре объявления, 194 байта). Основной CSS,
рабочий модуль, vendor, manifest и опубликованный профиль не изменены.
Это уменьшение повторов, а не подтверждённое ускорение.

## Почему блок выглядит избыточным

Первый блок уже задаёт те же border, color и box-shadow. Его background-color
имеет `!important` и выигрывает у второго блока с тем же значением.
Hover остаётся отдельным более специфичным правилом; transition и радиус
первого блока сохранены. Media и псевдоэлементы не меняются.

## Защищённая подстановка

Кандидат находится в игнорируемой `.preview/main1-button/main_code_1.css`.
Его SHA256 — `34dd4651c3514fba98e0be4b7475591b1afd1ce6f636ddeccf6cffcddec80c66`.
Для воспроизведения нужно взять vendor main1 и удалить только точную строку
`DUPLICATE_BUTTON_BLOCK` из `tools/preview/main1-button-pilot.mjs` один раз.

```powershell
node tools/preview/preview.mjs --main1-button-candidate .preview/main1-button/main_code_1.css --check-layout --widths 1440,390,360
pnpm --dir tools/preview test
```

Режим разрешает только это конкретное побайтное удаление. Проверяются прежний
snapshot и удалённые закреплённые источники. Остальные байты опубликованной
основы, включая преобразованные URL и Firefox fallback, сохраняются.
CSSOM обязан отличаться ровно одним разрешённым правилом. Дополнительная правка,
дублированный/отсутствующий блок и сочетание с другими CSS-миграциями отклоняются.
Это не универсальная подстановка изменённого модуля и не готовая новая версия
commit-URL для публикации.

Исходные строгие миграционные флаги не скрываются: полный CSSOM изменился,
поэтому `strictMigrationVerdict: FAIL`. Узкая проверка доказывает только ожидаемое
удаление и неизменность прочего. Если реальных кнопок нет, итог **INCOMPLETE**,
код завершения 2, `publicationReady: false`.

## Покрытие и ограничения

На публичных страницах профиля, достижений, аниме, клубов, коллекций,
пользователей, турниров и входа/регистрации реальных `.b-link_button` не найдено.
Авторизация не выполнялась. Пользователь разрешил продолжить подготовку без
ссылки на реальный компонент.

Явные тестовые примеры: ссылка, button и input с обычной и альтернативной
наследуемой палитрой. На 1440/390/360 px проверяются normal, hover, focus и active:
72 сравнения полной геометрии и вычисленных стилей, включая `::before`/`::after`.
Они не заменяют реальный интерфейс и не покрывают Firefox, авторизованные
страницы, неизвестные состояния и будущие обновления основы.

Отрицательные тесты проверяют отказ при посторонних изменениях байтов/CSSOM
и обнаружение намеренно изменённого псевдоэлемента. Тестовые документы работают
в standards mode; click и dragstart тестовых кнопок подавлены только в браузере
предпросмотра. CSS-анимации остановлены, GIF/WebP могут менять кадры.

Рабочий модуль оставлен прежним до проверки реального компонента. Следующий
шаг — найти такой DOM или выбрать отдельно согласованный кандидат с доступным
покрытием. Не переносить этот пилот автоматически в опубликованный импорт.

## Подключение после разрешения пользователя

Пользователь отдельно разрешил push и публикацию с известным пробелом реального
покрытия. Модуль main1 опубликован отдельным коммитом
`9c8e3373f0d65490823e609f56472fc168a9b8a7`; его новый закреплённый URL заменил
прежний URL в `styles_optimized.css`. Остальные импорты и настройки не менялись.
Vendor и `css/imports.json` сохранены как исходные эталоны.

`css/main1-optimization.json` описывает только эту замену и новый SHA256.
Обычный предпросмотр проверяет точное побайтное удаление из vendor, рабочий
файл и удалённый ответ. При смене URL он удаляет тот же блок из опубликованной
основы на прежнем месте. До публикации разница полного CSSOM — одно правило;
после публикации модель должна совпасть со всем новым серверным CSSOM.
Индексы старых URL-rewrite исключений смещаются на доказанное удаление,
контрольные суммы самих правил и проверка ресурсов сохранены.
