## Узкая проверка вместо эмуляции санитайзера

В `vendor/edesign-pins.json` сохранены конкретные `compiledUrlRewrites`:
индекс правила верхнего уровня, SHA256 его исходного CSSOM-текста, пары URL
и точное число вхождений. Исходные CSS сохранены целиком без изменения байтов.

`assertVersionPinRules` работает только для сравнения:

1. Проверяет индекс, уникальность и хэш каждого известного правила.
2. Для `/x/…` допускает лишь наблюдаемое раскрытие префикса без замены домена/пути.
   Для Camo требует точный хост `camo-v3.shikimori.io`, ожидаемый формат пути,
   единственный параметр `url` и совпадение декодированного адреса ресурса.
3. Меняет только настоящие `url("…")`-токены в копии CSSOM-массива для сравнения;
   проверяет число вхождений. Похожие строки внутри `content` не подменяются.
4. Сравнивает итоговый массив с реально опубликованным CSSOM целиком. Любое
   неизвестное отличие, включая другой Camo-адрес того же ресурса, даёт ERROR.

Сама foundation в предпросмотре сохраняет все старые CSS-правила побайтно;
меняются только комментарии-метки утверждённых URL импортов. Пары не используются
для записи новых ресурсных URL в CSS. Модель не вычисляет подписи Camo и не является
универсальной копией серверного санитайзера.

Сохраняются прежние проверки SHA256 локального snapshot и свежего pinned-ответа,
полного CSSOM кандидата, порядка импортов, геометрии и вычисленных свойств.
Main2/main3 по-прежнему требуют точного совпадения без исключений для URL.
Отрицательные тесты проверяют подмену ресурса/хоста, лишние параметры Camo,
изменение подписи, селектора, размера, позиции правила, хэша и количества URL.

## Ограничения и следующий шаг

При обновлении Chromium сериализация CSSOM может измениться. Новый формат Camo
или другое серверное преобразование тоже остановят проверку: нужно заново сверить
данные, а не добавлять общее игнорирование URL. Ресурсы не скачивались для анализа
кадров, и совпадение байтов изображений не утверждается.

Это завершение фиксации версий, а не перенос всех правил E-design в локальные
компоненты. Следующий шаг — подготовка полного проверенного источника-замены
и способа сохранять каскад при разделении основы. Частичное удаление правил
из внешнего импорта само по себе не поддерживается. Публикация и push требуют
отдельного разрешения на этот пакет.

Firefox, реальные устройства, авторизованные состояния и результат будущей
серверной загрузки новых import-URL не проверены. Снимки сохраняются, но вручную
не просматривались: здесь меняются только источники при идентичном полном CSSOM.
Неизменившиеся hover/анимации и media-границы повторно не прогонялись.

Все четыре remote-ответа и snapshot проверены по SHA256. Для main1 подтверждены
2 правила/4 URL-вхождения, для main4 — 5 правил/5 вхождений; для main2/main3
исключений нет. Отрицательные тесты отвергают изменения за пределами этих URL,
подмену ресурса и Camo-адреса, неверные хэши, индексы и числа вхождений.

SHA256 проверенного основного CSS:
`817e665fb6971f880087ed8961fe2fd4008a40866a003ea8e3a29d444ce62ae5`.
Аудит преобразований сохранён в `.preview/edesign-url-work/audit.json`.
Снимки сохранены, вручную не просматривались; это не отдельная визуальная оценка.
Публикация, OAuth, credentials и git push не использовались.

Исходные конечные пробелы main1/main4 сохранены ради байтовых хэшей. Атрибут
`whitespace=-blank-at-eol` задан только этим двум vendor-снимкам; локальный CSS
и инструменты сохраняют обычную проверку whitespace. LF задан всему `vendor/edesign/`.
