# Shikimori · SadLaboka

Кастомное оформление [профиля SadLaboka](https://shikimori.io/SadLaboka) и страниц
Shikimori: тёмная палитра, сине-малиновое свечение, анимированные изображения,
достижения и фильтры.

Оформление использует CSS-возможности Shikimori. Изменения HTML и скриптов сайта
для установки не требуются. Тема применяется также к каталогам, спискам и другим
страницам сайта в пределах настроек пользовательских стилей Shikimori.

## Установка

1. Откройте [styles_optimized.css](styles_optimized.css) и скопируйте **всё содержимое**.
2. В Shikimori откройте настройки профиля → редактор CSS / «Внешний вид сайта».
3. Сохраните копию своего прежнего CSS, вставьте новый и сохраните изменения.
4. Обновите страницу и проверьте профиль, список аниме и фильтры.

Сейчас файл содержит сторонние `@import` и собственные правила. Подключение всего
файла одним дополнительным `@import` пока не проверено: это создаёт вложенные импорты.
Проверенный способ установки — вставка содержимого целиком или отправка через API.

## Структура

```text
styles_optimized.css       Основной CSS, устанавливаемый в Shikimori
about.md                  BBCode содержимого раздела «Обо мне»
deploy.config.json        Шаблон несекретной конфигурации публикации
scripts/
  deploy.ps1              Проверка, backup, diff и публикация через OAuth2 API
tests/
  deploy.tests.ps1        Локальные проверки с подставным API
docs/
  deployment.md          Настройка и запуск публикации из Windows
  performance.md         Результаты экспериментов с производительностью
  architecture.md        Текущая основа и план модульной темы
```

Несмотря на расширение `.md`, `about.md` предназначен для редактора BBCode Shikimori.
Установка CSS сама по себе не заменяет содержимое «Обо мне».

## Публикация из Windows

Нужны PowerShell 7+ и Git. Подробная настройка OAuth и конфигурации описана в
[инструкции по публикации](docs/deployment.md). Если команда `pwsh` не найдена,
используйте полный путь к установленному PowerShell 7 или добавьте его в PATH.

```powershell
# Сначала сравнение без публикации
pwsh -NoProfile -File .\scripts\deploy.ps1 -DryRun -ConfigPath .\deploy.local.json

# Затем публикация с обязательным ручным подтверждением
pwsh -NoProfile -File .\scripts\deploy.ps1 -Publish -ConfigPath .\deploy.local.json

# Тесты: подставной API, без изменения профиля
pwsh -NoProfile -File .\tests\deploy.tests.ps1
```

Без переключателя скрипт работает в режиме dry-run. Перед PATCH он проверяет
аккаунт и владельца стиля, сохраняет backup и показывает diff. После отправки
проверяет совпадение сохранённого CSS. Push в GitHub и публикация в Shikimori —
разные операции: один лишь push через этот скрипт профиль не обновляет.

Токены и client secret вводятся локально и хранятся вне репозитория с защитой
Windows DPAPI. `deploy.local.json`, записи Firefox и локальные backup не входят
в публикуемую структуру. Не добавляйте секреты в CSS: его видят посетители профиля.

## Что изменено

- Сокращены повторяющиеся правила без смены оформления.
- Добавлена тёмная палитра новых выпадающих фильтров и выровнена их шапка.
- График активности переведён с анимации высоты и отступов на `clip-path`.
- Для избранного и достижений на широком экране включён экспериментальный
  `content-visibility`; заметное ускорение от него пока не подтверждено.

Ограничения и результаты замеров — в [заметках о производительности](docs/performance.md).

## Сторонняя основа

Текущая версия использует:

- [E-design / ed-main](https://github.com/ed-main/ed-main.github.io/tree/master/cssfiles):
  четыре основных CSS-файла, метки истории и анимированный график.
- [CSS-club](https://shikimori.io/clubs/811-css-club-nastroyka-vneshnego-vida-sayta):
  расположение блоков профиля и механизм замены постеров.
- Google Fonts: Rubik Spray Paint и DynaPuff.
- Изображения по внешним URL, указанным в CSS и BBCode.

Репозиторий содержит настройки и переопределения этой основы, а не полностью
самостоятельную тему. Источники остаются указаны в `@import`. У стороннего кода,
шрифтов и изображений свои авторы и условия использования; общая лицензия на них
здесь не заявляется.

## Дальнейшая работа

Планируется переход к отдельным CSS-модулям с фиксацией внешней основы и постепенной
заменой компонентов. Приоритет — сохранить текущий визуальный стиль. Конкретная
схема импортов и версионирования описана в [плане структуры](docs/architecture.md).
