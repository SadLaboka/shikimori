# Shikimori CSS · SadLaboka

Личное оформление https://shikimori.io/SadLaboka; публичный репозиторий
https://github.com/SadLaboka/shikimori, ветка `main`. Общайся по-русски, объясняй
просто. CSS действует на всём сайте; менять HTML и скрипты Shikimori нельзя.

## Постоянные правила

- Сохраняй внешний вид, изображения и анимации. Делай точечные правки;
  не ограничивай глобальные селекторы профилем автоматически.
- Не меняй внешние импорты без согласования. Учитывай каскад и специфичность;
  не удаляй массово повторы, `!important` и старые ошибки синтаксиса.
- Git push и публикация CSS требуют отдельных явных разрешений на конкретный
  пакет изменений. Не переспрашивай для уже разрешённого действия.
- Секреты не должны попадать в Git, чат, команды и логи. Не читай credentials
  без необходимости. OAuth, refresh и публикация — отдельные действия;
  не запускай их автоматически. Изображения не пересобирай и не загружай без согласия.
- Публикуй через `scripts/deploy.ps1`: предварительный diff, backup и сверка
  серверного `css` с проверенным снимком; dry-run доступен отдельно.
  Не повторяй PATCH вслепую после ошибки.
- Делай отдельные коммиты по смыслу; проверяй staged-файлы, не добавляй всё вслепую.
  Локальные настройки, captures, отчёты, backup и секреты не коммить.

## Основные пути

- `css/components/` — исходники, порядок в `css/components.json`; `about.md` — BBCode.
- `styles_optimized.css` — собираемый CSS; `node scripts/build-css.mjs --check` перед проверкой/выпуском.
- `vendor/` — исходники перенесённой основы; сохраняй авторство.
- `tools/preview/` — Playwright; результаты в игнорируемой `.preview/`.
- `deploy.config.json` — шаблон; `deploy.local.json` — игнорируемые настройки.

## Выбор проверок и чтения

Читай только нужные разделы и файлы; начинай с поиска. Старые отчёты не загружай
по умолчанию. Не повторяй успешные проверки без новых изменений или неопределённости.
Для разрешённых push/публикации используй короткий [порядок выпуска](docs/release.md):
не начинай повторный аудит CSS; привязывай проверенный результат к SHA256.

- Для статического анализа и документации браузер не нужен. Проверяй ссылки,
  diff и корректность инструкций. Не выдавай это за проверку оформления.
- Для CSS проверяй синтаксис, затронутые селекторы, media и состояния в браузере.
  Для дизайна/оптимизации используй `.agents/skills/shikimori-css-design/SKILL.md`.
  Для миграции используй `.agents/skills/shikimori-css-migration/SKILL.md`:
  обязательные проверки эквивалентности не сокращать ради экономии.
- Для изменений deploy запускай `tests/deploy.tests.ps1` с подставным API;
  реальные токены не заменяют тестовые данные. Нужен PowerShell 7+.
- Перед завершением: `git diff --check`, краткий результат, ограничения проверок.
  Не обещай ускорение без измерений и PASS без покрытия компонента.
