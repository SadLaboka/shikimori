# Цветовые схемы Shikimori для Firefox

Личное расширение для аккаунта **SadLaboka**. Две готовые схемы: «Основная» и
«Emerald & Scarlet». Нажатие «Применить» сохраняет CSS в настройках аккаунта
через API Shikimori. Изменение увидят посетители, которым сайт показывает эту тему.
Переключение схем не запускает GitHub Actions; он используется только при выпуске
новой версии самого расширения. Предпросмотра перед сохранением нет.

## Установка для использования и проверки

Нужен Firefox для компьютера версии 140 или новее.

Для постоянной установки скачай [подписанный XPI 0.2.1](https://github.com/SadLaboka/shikimori/releases/download/firefox-v0.2.1/shikimori-schemes-0.2.1.xpi)
и установи через `about:addons` → ⚙ → «Установить дополнение из файла…».
Подпись Mozilla и работа после перезапуска Firefox 159 проверены.

Временная установка исходников для разработки:

1. Открой `about:debugging#/runtime/this-firefox` в адресной строке Firefox.
2. Нажми «Загрузить временное дополнение…» и выбери `manifest.json` из этой папки
   либо подготовленный `shikimori-schemes-0.2.2.zip`.
3. Открой `https://shikimori.io/`, войди как SadLaboka и нажми значок расширения
   в меню дополнений Firefox. При необходимости закрепи его на панели.

Временная установка действует до закрытия Firefox. Локальные ZIP/XPI, созданные
сборщиком, не подписаны. Подписанная версия выпускается автоматически в режиме
Unlisted, без публичной карточки в каталоге Mozilla.

Не загружай архив или папку `.preview/` целиком: готовый пакет содержит только
перечисленные в сборщике файлы расширения.

## Использование

Оставь открытой хотя бы одну вкладку `shikimori.io` в текущем окне Firefox.
Сначала расширение проверяет аккаунт и читает текущий CSS. Затем выбери схему
кнопкой «Применить». Круглая стрелка повторно читает состояние сервера;
она не ищет обновления в GitHub.

В версии 0.2.0 обычное нажатие на круглую анимированную картинку поверх аватарки
в профиле SadLaboka переключает схемы по кругу: **Основная → Emerald & Scarlet →
Основная**. Дополнительного меню нет. Сначала читается актуальное состояние
сервера; старое состояние меню не используется. Порядок явно задан в
`CYCLE_ORDER` и не меняется автоматически при перестановке карточек.

Обрабатываются нажатия внутри скруглённой квадратной рамки, включая мобильный размер;
кнопки действий под аватаркой, другие профили и клики с Ctrl/Alt/Shift/Meta
не запускают переключение. Доступны также Enter и пробел при фокусе на аватарке.
Повторный клик во время операции блокируется. Страница показывает этапы и
результат; неопределённый результат нужно проверить в меню расширения.
Чужой аккаунт, неизвестный CSS или незавершённая запись не перезаписываются.

Увеличение на 7% и плотное свечение акцентным цветом по квадратной рамке
со скруглёнными углами — часть CSS обеих схем. Сама картинка остаётся прежней:
после сохранения обновлённой схемы они видны посетителям и без расширения.
При уменьшении движения свечение сохраняется, увеличение и переход выключены.
Новая версия отправляет те же семь закреплённых импортов и небольшой блок этого
эффекта после них. Поэтому первое успешное переключение через 0.2.2 устанавливает
эффект без изменения ссылок GitHub. Только замена установленного расширения
сама по себе CSS на сервере не публикует.

«Вернуть предыдущий CSS» восстанавливает сохранённое расширением оформление.
В Firefox хранятся последние пять копий исходного CSS. При удалении расширения
его локальные копии удаляются вместе с ним. Если CSS был отредактирован вне
расширения, устаревшее состояние не перезаписывается: нужно повторно прочитать
состояние и осознанно выбрать схему.

По умолчанию после успешной записи обновляется текущая вкладка, если это та же
вкладка Shikimori, через которую выполнена операция. Другие вкладки не обновляются.
Этот режим можно отключить галочкой в меню. Если вкладка уже находится в фоне,
обнови её вручную, чтобы увидеть новую схему.

После потери ответа нажми «Проверить результат». Повторной отправки PATCH нет.
Если сервер пока хранит прежний CSS, новая запись разрешается только после
повторной проверки спустя минуту. Ошибки загрузки импортов сообщаются отдельно:
сохранённый CSS сам по себе ещё не означает, что Shikimori загрузил все ресурсы.

## Доступ и данные

Расширение использует уже выполненный вход в Firefox. OAuth-приложение, access token,
refresh token и client secret не требуются. Оно не читает хранилище токенов deploy
и не запрашивает доступ к cookie API. Запросы выполняются из изолированного скрипта
во вкладке Shikimori с обычной сессией сайта. CSRF-токен берётся из метатега страницы
только в памяти запроса и не записывается в хранилище или журналы.

Доступ к страницам ограничен `https://shikimori.io/*`. Проверяются ID и имя аккаунта,
ID и владелец стиля, актуальность исходника до PATCH и точность сохранения после него.
При выборе вкладки учитывается текущий вход, в том числе контейнер Firefox;
при нескольких разных сеансах открой нужную вкладку перед вызовом меню.
Запись в чужой аккаунт или другой стиль не поддерживается.

В локальном хранилище расширения находятся резервные CSS, их контрольные
суммы, время, журнал незавершённой операции и настройка обновления вкладки.
Текст выбранного CSS отправляется исключительно Shikimori по действию пользователя.
Аналитики и стороннего сервера расширения нет. Встроенное разрешение Firefox
`websiteContent` описывает передачу CSS сайту. В `storage.session` хранится счётчик
запросов. Изолированный обработчик аватарки локально добавляет клавиатурный фокус
и текстовое уведомление о ходе операции. Исходники HTML и JavaScript Shikimori
не редактируются. Эффект наведения сохраняется в CSS аккаунта обычной публикацией;
локальная подстановка другой схемы до сохранения не выполняется.

## Как устроены схемы

`catalog.mjs` содержит небольшие готовые блоки: два импорта шрифтов, четыре
существующих импорта основы и ссылку на полный файл выбранной схемы. Все ссылки
на CSS GitHub закреплены конкретными коммитами. Расширение не получает файлы
с GitHub: их загружает сам Shikimori при обработке CSS.

Пакет 0.2.2 фиксирует полные файлы схем на коммите
`e4f9fe9118d6d81397e069254da91ee4f728d3da`. Новые схемы и версии добавляются
изменением каталога и выпуском новой версии расширения. Новую комбинацию импортов
нужно проверять компиляцией: единственный импорт полного файла теряет вложенные
импорты Shikimori. Блок наведения из `avatar-hover.mjs` сверяется тестом
с `css/components/22-avatar-interaction.css` с нормализацией переводов строк;
этот компонент входит в обе актуальные сборки.
Распознаются исходные полные CSS, сборки 0.2.1 и актуальные сборки, а также
прежние блоки семи импортов с круглым свечением и без него. Обновление
с 0.1.x и 0.2.1 сохраняет возможность переключения и возврата.

Расширение — отдельно запрошенный пользователем способ прямого сохранения через API.
Обычная публикация из терминала по-прежнему выполняется через `scripts/deploy.ps1`.

## Быстродействие

Проверка аккаунта и чтение текущего CSS выполняются параллельно. Перед PATCH
по-прежнему сохраняется резервная копия и повторно проверяется исходник,
а после PATCH результат отдельно читается с сервера.

Вместо обязательных пауз по 700 мс применяется общий для расширения ограничитель:
не более пяти запросов за 1100 мс и 80 за 60025 мс. Одна проверенная публикация
содержит пять запросов и помещается в свободный секундный бюджет. Сохраняются
запас по длительности окна и минутному лимиту Shikimori (5 запросов в секунду,
90 в минуту). Запросы в полёте также
занимают место; счётчик сохраняется в `storage.session` между перезапусками
фоновой страницы. Пока бюджет свободен, дополнительной фиксированной паузы нет.

Обработчик аватарки использует уже загруженный изолированный скрипт без повторной
инъекции при каждом клике. В Firefox 159 с тестовым API (100 мс на ответ)
и одинаково свободным секундным бюджетом время от нажатия до события загрузки
вкладки составило 1264 мс в 0.2.1 и 453 мс в 0.2.2. Кнопка меню заняла
1255 и 441 мс соответственно. Это проверка локального пути запросов:
тестовая страница не воспроизводит компиляцию CSS и загрузку ресурсов Shikimori.

GET текущего стиля использует HTTP `no-cache`: браузер обязан проверить ответ
у сервера и может использовать ETag, чтобы не получать тот же большой JSON
повторно. Это не разрешает чтение старого CSS без проверки. Аккаунт и запись
всегда обходят HTTP-кеш (`no-store`).

Меню показывает этапы проверки, сохранения копии, публикации и сверки результата.
Индикатор учитывает настройку уменьшения движения Firefox. Если открыть меню
во время операции, оно проверяет готовность фона каждые 150 мс без отправки
дополнительных HTTP-запросов до завершения текущей операции.

Время самой компиляции Shikimori, полной перезагрузки страницы и загрузки фонов
остаётся зависимым от сервера и сети. Локальная подмена стиля без перезагрузки
в эту версию не включена: прежние проверки Firefox выявляли расхождения при
такой замене. Ускорение запросов расширения не гарантирует такую же разницу
во времени полной отрисовки страницы.

## Разработка и сборка

Из корня репозитория:

```powershell
node --test tests/firefox-extension.test.mjs tests/firefox-rate-limit.test.mjs tests/firefox-avatar.test.mjs
node tests/firefox-extension-native.mjs
pwsh -NoProfile -File scripts/package-firefox-extension.ps1
```

Браузерный тест использует обычный установленный Firefox Windows (либо путь
`SHIKIMORI_TEST_FIREFOX`, с резервным вариантом из `tools/preview/`), собственный
профиль и стандартный протокол WebDriver BiDi. Нужен Node.js 22 или новее.
Служебный скрипт в тестовой копии открывает неизменённое меню API Firefox;
он не меняет код публикации, запросы или UI и не включается в пакет.
HTTPS перехватывается до открытия Shikimori; используются только
подставная сессия, CSRF и API. Реальные токены и профиль пользователя не используются.
Снимки и отчёт находятся в игнорируемой `.preview/firefox-extension/`.

Для замера с одинаковой подставной задержкой API 100 мс:

```powershell
node tests/firefox-extension-native.mjs --performance-label=current
```

Времена открытия меню, применения и возврата записываются в
`.preview/firefox-extension/performance/current.json`. Это измерение расширения
на подставном сервере, без оценки времени компиляции живого Shikimori и загрузки
его реальных изображений. Проверки успешного сохранения и возврата при этом
продолжают выполняться.

Пакет собирается из явного списка файлов, без настроек, токенов, резервных копий,
тестов и отчётов. ZIP и неподписанный XPI записываются в эту же игнорируемую папку.

## Автоматический выпуск и обновления

Начиная с 0.2.1 манифест содержит `update_url` постоянного файла
`releases/download/firefox-updates/updates.json` этого репозитория. После первой
ручной установки подписанного XPI Firefox проверяет этот адрес и может сам
устанавливать следующие подписанные версии. Старые пакеты 0.1.x/0.2.0 без
`update_url` нужно один раз обновить вручную. Временное дополнение остаётся
временным и подписью или автообновлениями не заменяется автоматически.

Workflow `Release Firefox extension` запускается отметкой `firefox-v<версия>`
или вручную с уже существующей отметкой. Версия должна совпадать с манифестом,
а коммит входить в `main`. Нужны секреты репозитория `AMO_API_KEY` (JWT issuer)
и `AMO_API_SECRET` (JWT secret). Значения не включаются в пакет, исходники или
аргументы команд. Доступ к ним есть только у шага подписи.

Проверки выполняются до отправки. Существующая версия AMO читается и используется
повторно; ожидающая рассмотрения версия не загружается заново. Подписанный пакет
сверяется с проверенным исходным пакетом, затем публикуется в отдельном выпуске
GitHub. Список обновлений переключается после появления XPI и включает SHA512.
Отправка в AMO не гарантирует немедленной подписи: решение остаётся за Mozilla.

Подробности и восстановление после ошибок: [порядок выпуска](../../docs/firefox-release.md).

Источники платформенных требований:
[Mozilla: content scripts](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Content_scripts),
[HTTP-кеш](https://developer.mozilla.org/en-US/docs/Web/API/Request/cache),
[лимиты API Shikimori](https://shikimori.io/api/doc/1.0.html),
[подпись и распространение](https://extensionworkshop.com/documentation/publish/signing-and-distribution-overview/).
