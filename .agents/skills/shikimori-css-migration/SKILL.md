# Shikimori CSS migration

Соблюдай [AGENTS.md](../../../AGENTS.md). Workflow не использует deploy/OAuth/секреты,
не публикует CSS и не делает push. Новые зависимости, MCP и сборщик — лишь при необходимости.

## Режим

**Анализ:** импорт и связанные локальные правила. Документы — по вопросу:
[архитектура](../../../docs/architecture.md) для CSS/разметки,
[журнал](../../../docs/style-migration.md) для статуса и зависимостей.
Старые аудиты — по конкретной зависимости. CSS/vendor/инструменты не менять.
Без тестов/Playwright для статической задачи; браузер — если нужна проверка на сайте.
Результат: план, риски, непроверенные предположения; не PASS.

**Перенос:** нужные разделы [preview.md](../../../docs/preview.md), CLI и покрытие.
Код инструментов читай при адаптации/сбое; историю заранее не загружай.

## Обязательные этапы переноса

1. Сверь исходник с развёрнутым `style#custom_css`; сохрани снимок, хэш, авторство.
   Выбери небольшой независимый блок и затронутые страницы.
2. Проверь порядок, специфичность, `!important`, shorthand, media/layer/scope,
   переменные, URL, псевдоэлементы и состояния. При перестановке проверь все
   пересечённые правила, включая AUTO. Без одновременной оптимизации.
3. Кандидат — в `.preview/`, с исходными окончаниями строк. Удаляй импорт только
   при полном переносе. Замени прежний лист, убрав лишь выбранный блок основы;
   наложение копии не является заменой.
4. Проверь CSSOM: число, происхождение, порядок, условия правил; отсутствие старых
   копий/дублей; остальные правила, позицию листа и хэш кандидата.
5. На целевой странице проверь 1440/390/360px и релевантные media-границы:
   геометрию, вычисленные стили, псевдоэлементы, применимые hover/focus/active,
   локали, фазы анимаций. Ноль мишеней — не PASS; примеры не заменяют реальный DOM.
6. Запусти `pnpm --dir tools/preview test` и релевантный строгий режим.
   Для нового переноса временной копией проверь обнаружение пропуска правила,
   включая неактивную media-ветку. Защиты не ослабляй.
7. Сохраняй снимки. Сначала читай сводку/покрытие; открывай целевые изображения
   при необъяснённом diff, пробелах покрытия, нужной визуальной оценке или запросе.
   Не просматривай все картинки/старые отчёты автоматически.
   GIF/WebP не заморожены; pixel diff не доказывает ошибку или эквивалентность.
8. Исправь ошибки, повтори затронутые проверки. После успеха скопируй кандидат
   в основной CSS, сверь хэш, повтори предпросмотр. Полный набор состояний для
   тех же байтов не повторяй без новой причины. При критическом сбое или недоказанной
   эквивалентности остановись; непроверенный CSS в основном файле не оставляй.

## Покрытие и отчёт

CLI: `--component profile|history`, `--css`, `--widths`; replay — см. preview.md.
Профиль: `--check-layout`, `--check-activity`, `--check-posters`; история: `--component history --check-history`.
`--url` отсутствует. За запуск разрешён полный перенос одного известного импорта:
раскладка, q03, q05 или постеры. Для нового компонента сначала обеспечь аудит; прежний PASS
его не покрывает. Фиксация версий — отдельный путь по `vendor/edesign-pins.json`,
со сверкой байтов и CSSOM; детали в preview.md.

Отчёт: изменения, результаты, исправления, пропуски, риски обновления основы;
ссылки на текущие локальные HTML-отчёты и нужные снимки. Отметь, если изображения
не просмотрены: машинный PASS не заменяет визуальную оценку и не закрывает её пробелы.
Проверяй текущий кандидат, не ссылайся на старый PASS.
