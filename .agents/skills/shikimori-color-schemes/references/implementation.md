# Сборка и ресурсы отдельной схемы

## Что уже есть в проекте

- `scripts/build-css.mjs` экспортирует `assembleCss(root)` и собирает общие
  компоненты без преобразований. Его `--output` допускает только основной файл
  или `.preview/`; произвольный `css/themes/...` этим флагом не поддерживается.
- `scripts/build-emerald-scarlet.mjs` — рабочий пример отдельной сборки:
  общие компоненты → замены литералов из `colors.json` → `palette.css` в конце.
  Его пути и команды привязаны **только** к Emerald & Scarlet. Само создание
  папки новой схемы не делает этот скрипт универсальным.
- Для новой схемы подготовь явно выбранную сборку: небольшой отдельный entrypoint
  или, когда это оправдано, параметризуй общий инструмент. Не переписывай рабочую
  сборку существующей схемы на другой slug. При изменении инструментов проверь
  их инварианты и неизменность результата для уже существующих схем.

Кандидат, итоговый файл и режим проверки должны выбирать одну схему явно.
Сборка не должна менять исходники, vendor, импорты, URL или CSS другой схемы.
Преобразование литералов пропускает комментарии, строки и `url(...)`; параметры
цветовых функций, кроме согласованных каналов, сохраняются. Существующий
`recolorCss` покрывает конкретные hex/RGB-литералы; не считай его CSS-парсером
для HSL, современного RGB-синтаксиса, вложенных функций и любых будущих цветов.

Проверки сборки должны подтверждать сохранение общей основы, импортов,
неизменяемых URL и анимационного timing. Новые URL схемы — отдельные ожидаемые
добавления. Перед записью результата сверь его с проверенным кандидатом,
после записи — SHA256. При проверке существующих схем не перезаписывай их файлы.

## Изображения и каскад

Ищи актуальные селекторы в исходниках, а затем подтверждай их в настоящем DOM.
Ниже — ориентиры, а не универсальные селекторы для любого будущего профиля:

| Ресурс | Где искать | Особенность |
| --- | --- | --- |
| Два фона | `05-palette-background.css`, `body::after` | В Emerald & Scarlet слева/справа, `contain`, без повторения, от 1280 px |
| Баннер имени | `12-profile-content.css`, `.aliases` | Переопределяй `background-image`, сохрани геометрию и hover-scale |
| Аватар профиля | `11-entry-avatar.css`, `.avatar::before` | У списка аниме есть отдельная картинка; не заменяй её автоматически |
| TOP/TIERLIST | `about.md`, изображение внутри ссылки | Для отдельной схемы возможен `content: url(...)` у точного существующего `img` |

Селектор TOP/TIERLIST должен находить нужную картинку, не затрагивая все изображения
«Обо мне». Сайт/модель обработки CSS нормализует HTTP(S)-ссылки, в том числе строки
в селекторах. Exact `href="https://..."` в проверенном случае переставал совпадать
после нормализации; используй устойчивый селектор без протокола и проверь число
мишеней. Это не разрешение расширять селектор на произвольные картинки.

`content: url(...)` не меняет HTML-атрибут `src`: DOM `naturalWidth` может относиться
к прежнему изображению. Проверь вычисленное `content`, фактическую загрузку нового
ресурса и снимок. До сравнения геометрии дождись декодирования исходной картинки:
незагруженный `img` может иметь временную нулевую ширину.

Если меняешь только картинку, предпочитай `background-image`, а не shorthand
`background`, чтобы не сбросить положение, размер и повторение. Проверь псевдоэлемент
и мобильные overrides. Для границы фонового media проверь ширины по обе стороны;
для композиции — широкий экран, где видны обе стороны, а не только 1440 px.

## Выпуск и возврат

Основной CSS не всегда равен текущему опубликованному. При разрешённом выпуске
сверь серверный backup с тем снимком, который собираешься назвать основной темой.
Если они различаются, не перезаписывай ни один и объясни, какой файл вернёт какую
схему. Сохраняй проверенные CSS, их хэши и команды возврата в игнорируемом каталоге;
не полагайся только на изменяемую рабочую копию или старый путь в `.preview/`.
Штатный deploy также сохраняет резервную копию вне репозитория.

Команда публикации должна содержать явные `-CssPath`, `-ConfigPath` и
`-ExpectedCssSha256`; значение SHA берётся из конкретной проверки, не из примера.
Дальнейшие действия — по `docs/release.md`. После нового способа подключения URL
проверь реальный скомпилированный CSS/CSSOM. Возврат использует тот же deploy
и доступ к API; скрипт отката не отменяет требований к действующим credentials.
