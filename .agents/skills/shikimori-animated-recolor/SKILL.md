# Перекраска анимаций Shikimori

Соблюдай [AGENTS.md](../../../AGENTS.md). Цель — отдельный готовый файл под палитру,
а не замена оригинала, публикация или загрузка на фотохостинг.

## Выбор способа

Учитывай доступные инструменты редактирования и их ограничения. Этот навык сам
по себе не разрешает обходить обязательный imagegen или использовать скрипт.
Если пользователь уже явно выбрал покадровую обработку скриптом, сохраняй это
разрешение в рамках продолжающейся работы и не спрашивай его заново. Если способ
ещё не выбран, а инструмент не сохраняет анимацию, объясни ограничение и получи
нужный выбор, прежде чем переходить к покадровой обработке. Разрешение на новую
схему само по себе не разрешает пересобирать её картинки.

## Найти и понять оригинал

- Ищи URL в соответствующем компоненте или `about.md`. Для известных мест
  используй [карту ресурсов](../shikimori-color-schemes/references/implementation.md).
  Не определяй формат только по расширению: TOP/TIERLIST первоначально был GIF.
- Используй доступную локальную копию с известным источником или скачай только
  нужный публичный ресурс. `.image-audit/` может отсутствовать; не делай сохранённые
  отчёты обязательной зависимостью. Не копируй все старые исходники в новую схему.
- Запиши SHA256 исходника, формат, размеры, число кадров, loop и длительность
  каждого кадра. Для Pillow читай duration после `seek()` и `load()`; работай
  с полными RGBA-кадрами после compositing/disposal, не с сырыми дельтами GIF.
- Посмотри репрезентативные кадры на тёмном фоне и фактическую анимацию.
  Определи, перекрашивается весь цветовой диапазон или отдельная область.

## Покадровая обработка, когда она выбрана

Используй Python/Pillow; путь к runtime и пакетам найди через доступный инструмент
workspace dependencies, не полагайся на WindowsApps `python.exe` или чужой абсолютный
путь. NumPy полезен для масок, но не является обязательным форматом реализации.
Алгоритм, варианты и проверки храни в `.preview/`; готовые выбранные изображения —
в `css/themes/<slug>/assets/`. Не ссылайся из готовой темы на временный каталог.

- Обрабатывай оригинал, а не предыдущую сжатую версию. Не меняй исходный файл.
  Новую редакцию сохраняй отдельно или заменяй только явно редактируемый вариант,
  сохранив предыдущий результат локально при необходимости.
- Ограничь преобразование маской по цвету и, если нужно, области кадра.
  Белые фигурки, контуры и нейтральные блики не должны окрашиваться вместе с фоном.
  Не растягивай вручную найденные координаты одного изображения на другое.
- Сохрани размеры, порядок и число кадров, alpha, loop и массив durations.
  Не меняй FPS, не удаляй повторы и не оптимизируй движение без отдельной задачи.
- Сначала оцени цвет на нескольких кадрах, затем кодируй весь цикл.
  Проблемы смешивания и тёмного красного описаны в
  [рекомендациях по цвету](references/color-and-validation.md).
- Для небольших простых анимаций предпочитай lossless WebP. Для сложных предложи
  разумный размер/качество по измеренному результату. Не называй lossy-сжатие
  сохранением RGB без потерь. Пиши кандидат во временный файл и заменяй выбранный
  результат после проверки, чтобы ошибка кодирования не оставила пустой WebP.

## Проверка и передача

Открой итоговый закодированный файл заново. Сверь число кадров, размеры, loop и
каждую duration; alpha — попиксельно на всех кадрах. Для lossless проверь видимый
RGB, при локальной маске — неизменность видимых пикселей вне неё. Для lossy явно
разделяй неизменность преобразования и погрешность повторного кодирования.
Проверь, что исходный SHA256 не изменился. Если кодер объединил кадры, не выдавай
это за сохранённое число кадров: настрой кодирование или явно разбери различие.

Просмотри декодированные кадры и воспроизведение в браузере; одна контактная
таблица не доказывает анимацию. Дай пользователю файл, размер и ограничения.
После получения URL с хостинга проверь именно размещённый ресурс, затем подключи
его через [навык схем](../shikimori-color-schemes/SKILL.md) только к нужной схеме.
Публикация CSS остаётся отдельным действием.
